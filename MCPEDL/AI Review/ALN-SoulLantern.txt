# mcpe-pack-update: Update Delivery

## Authority

- `INSTRUCTIONS.md` is the policy source. `PACK_GENERATOR_INSTRUCTIONS.md` is its standalone copy for generation. The script flow is `INSTRUCTIONS.md` "Termux Script Rules", built with `scripts/make_update_script.py`. Where to look each rule up: the `mcpe-context7` skill. This skill is a short working checklist and never restates or overrides them.
- **Precedence** (as in `PACK_GENERATOR_INSTRUCTIONS.md`): factual accuracy and the user's requested scope, then Part 1, then Part 2, then this skill. Part 4 of the generator file never overrides Parts 1 and 2.
- If these files disagree with each other or with a script in `scripts/`, tell the user exactly what differs instead of choosing silently. If `INSTRUCTIONS.md` cannot be read, stop and report it instead of working from memory.
- Achievements line (every project type): always `Yes, achievement-friendly.` Keep any cheats or world-setting caveat as a following sentence.

## Scope

- Use for changes to an existing project (`MCPEDL/Addons|Maps|Script|Minigame/<Name>/`), a workflow, a script, a catalog or any repo doc.
- Read-only audit or report: use `checkrm`.
- New project from an idea: follow `PACK_GENERATOR_INSTRUCTIONS.md` Part 4 (ask the type first, base64 payload).

## Procedure

1. Read `INSTRUCTIONS.md` Parts 1 and 2 before writing anything, through Context7 as the `mcpe-context7` skill says. `make_update_script.py`, `apply_update.py`, and `pixel_json_to_png.py` are complete in the pack's review zip (`<Pack>.zip`) under `files/`; run them from there.
2. Find the destination folder: the path the user named, otherwise the matching project folder. Do not substitute a similar name; report ambiguity or a missing target.
3. Read the real source (manifests, scripts, items, recipes, loot tables, functions, lang files) before writing any claim. Source priority when sources disagree: the project's own files, Mojang Bedrock Samples, official Minecraft Creator Documentation, Minecraft Wiki, Bedrock Wiki.
4. Make the smallest possible change. No unrelated rewrites. Never invent features, versions, links, assets, test results or compatibility. Never write comments in shipped `.js`, `.mcfunction` or `.json` files.
5. Generate the spec, convert it with `make_update_script.py` into a single self-contained `<Pack>_v<Version>_<rand>.sh` file, and provide the one-line run command for the user.

## The update script

Generate the spec with `apply_update.py` directives (replace, replace-all, insert-after, insert-before, create, overwrite, delete, changelog).
Then build the single `.sh` using:
```bash
python3 files/scripts/make_update_script.py spec.txt --out-dir .
```
This produces ONE single `.sh` file (`<PackName>_v<Version>_<rand>.sh`) that contains the embedded update payload, ANSI colored status UI, automated git rebase, validation checks, commit, and push.

## Reply

2. Give the single Termux command:
```bash
bash ~/storage/downloads/<PackName>_v<Version>_*.sh
```
3. Brief summary of what changed and what checks ran.
4. **Save in AI memory**: Every finished output, applied change summary, and spec version must be retained in AI memory/scratch notes so context is preserved across turns without relying on session replay.

# scripts/lib

scripts/lib/ holds no .js files yet. Everything lives in scripts/main.js.

## Files

- scripts/main.js: registers all Soul Lantern behavior. Depends on @minecraft/server and @minecraft/server-ui.
- scripts/lib/README.md: this file.

## What main.js does

- Before-event on player interaction with an entity: a sneaking player holding aln:soul_lantern seals the target mob. The mob is saved with a world structure (entities only), its id and display facts are stored on the item as dynamic properties, and the item becomes aln:soul_lantern_filled.
- Before-event on player interaction with a block: aln:soul_lantern_filled places the saved structure on top of the clicked block, renames the mob if a lantern name was set, deletes the structure, and returns an aln:soul_lantern.
- After-event on item use: aln:soul_lantern_filled opens the Spirit menu (details, Project Spectral Ally, Rename Captured Mob). aln:soul_lantern shows a hint.
- Repeating timer every 4 ticks: ends spectral allies after 400 ticks, teleports one back to its owner when it strays over 16 blocks, spawns the particle trail, and detonates Kamikaze Spirits next to a monster.
- World load: removes leftover entities tagged aln_spirit.

## Ids

- Items: aln:soul_lantern, aln:soul_lantern_filled.
- Recipes: aln:soul_lantern_soil, aln:soul_lantern_sand.
- Dynamic properties on the filled item: aln_sid, aln_type, aln_name, aln_hp, aln_max_hp, aln_baby, aln_details, aln_rename.
- Entity: aln:spirit, tag aln_spirit, events aln:mode_<mode> and aln:fig_<n>. Structure ids: aln:soul_<random>.

## Known limits

- Bosses (Ender Dragon, Wither, Warden, Elder Guardian), players, armor stands, NPCs and agents cannot be sealed.
- The Spectral Ally is a light-blue, slightly transparent spirit entity that never attacks players. It wanders and fights like a pet using its own AI.
- Its attack mode (melee, fast, heavy, kamikaze, archer, snow) and the small figure inside come from the captured mob type. Mobs without a figure show a glowing soul orb.
- Villager profession is kept by the saved structure but is not shown in the menu.
- Cooldowns and active allies reset when the world reloads.
- Not tested in game.

function tryRelease(player, dim, blockLoc, slot) {
  const container = containerOf(player);
  const held = container?.getItem(slot);
  if (!container || held?.typeId !== FILLED_ID) return;

  if (typeof d.sid !== "string" || !d.sid) {
    tell(player, "§c", "This lantern holds no soul.");
    return;
  }
  let cell;
  for (let up = 1; up <= 4 && !cell; up++) {
    const c = { x: blockLoc.x, y: blockLoc.y + up, z: blockLoc.z };
    const low = dim.getBlock(c);
    const high = dim.getBlock({ x: c.x, y: c.y + 1, z: c.z });
    if (low?.isAir && high?.isAir) cell = c;
  }
  if (!cell) {
    tell(player, "§e", "There is no free space to release the soul here.");
    return;
  }
  const center = { x: cell.x + 0.5, y: cell.y + 0.5, z: cell.z + 0.5 };
  const before = nearbyIds(dim, center);
  try {
    world.structureManager.place(d.sid, dim, cell, { includeBlocks: false, includeEntities: true });
  } catch (e) {
    tell(player, "§c", "The soul could not be released.");
    return;

  container.setItem(slot, new ItemStack(EMPTY_ID, 1));
  burst(dim, center);
  play(player, "random.orb");

    } catch (err) {}
  }, 4);
}

    return;

  for (const [id, s] of spirits) {
    if (s.owner.id === player.id) endSpirit(id, undefined);
  }
  const d = readStack(held);
  const plan = SPECIES[d.type] ?? { fig: 0, mode: "melee" };
  const dim = player.dimension;
  const p = player.location;
  let spirit;
  try {
    spirit = dim.spawnEntity(SPIRIT_ID, { x: p.x + 1.5, y: p.y, z: p.z });
  } catch (e) {
    tell(player, "§c", "The spirit could not take shape.");
    return;
  }
  try {
    spirit.triggerEvent(`aln:mode_${plan.mode}`);
    if (plan.fig > 0) spirit.triggerEvent(`aln:fig_${plan.fig}`);
  } catch (e) {}
  try {
    spirit.addTag(SPIRIT_TAG);
    spirit.nameTag = `§b${d.name || d.species} §3(Spirit)`;
    spirit.addEffect("resistance", SPIRIT_TICKS + 40, { amplifier: 4, showParticles: false });
  } catch (e) {}
  spirits.set(spirit.id, { entity: spirit, owner: player, end: system.currentTick + SPIRIT_TICKS, mode: plan.mode });
  cooldowns.set(player.id, system.currentTick + COOLDOWN_TICKS);
  burst(dim, spirit.location);
  play(player, "block.amethyst_block.chime");
  tell(player, "§b", "Spectral Ally projected for 20 seconds.");
}

        s.entity.teleport({ x: p.x + 1, y: p.y, z: p.z + 1 }, { dimension: s.owner.dimension });
        continue;
      }
      dim.spawnParticle("minecraft:endrod", { x: at.x, y: at.y + 0.7, z: at.z });
      if (s.mode === "kamikaze" && ownerGap > 3.5) {
        const foe = dim
          .getEntities({ location: at, maxDistance: 2.4, families: ["monster"] })
          .find((e) => e.id !== s.entity.id && !e.hasTag(SPIRIT_TAG));
        if (foe) {
          dim.createExplosion(at, 2.5, { breaksBlocks: false, causesFire: false, source: s.entity });
          endSpirit(id, "Your Kamikaze Spirit detonates.");
        }
      }
    } catch (e) {}
  }
}, 4);

  for (const name of ["overworld", "nether", "the_end"]) {

**Seal any mob in a Soul Lantern, then release it or project a 20-second Spectral Ally.**

> Craft the lantern from glass panes, iron nuggets, soul soil or soul sand, and an amethyst shard, then carry a trapped creature with you.

## Overview

ALN SoulLantern adds one relic with two looks. The Empty Soul Lantern holds a faint pale-blue mist, and the Soul-Bound Soul Lantern glows with turquoise soul fire and floating embers.

Sneak and interact with a mob to seal it inside. The lantern shows the creature's name, health, and variant, and you can release it later on any block.

## Key Features

### Soul Lantern Crafting
- **What Happens**: Craft the lantern with 2 glass panes, 4 iron nuggets, 1 amethyst shard, and 1 soul soil or soul sand.

### Mob Capture
- **What Happens**: Sneak and interact with a mob while holding an Empty lantern. The mob vanishes in a swirl of soul particles and the lantern turns turquoise.

### Boss Protection
- **What Happens**: The Ender Dragon, Wither, Warden, and Elder Guardian cannot be sealed. The lantern trembles and a warning appears above the hotbar.

### Saved Mob State
- **What Happens**: The lantern keeps the mob's health, custom name, age, color, tamed state, equipment, and villager trades, and updates its own name and lore to match.

### Block Release
- **What Happens**: Interact with a block while holding a Soul-Bound lantern to place the saved mob on top of it. The lantern returns to the Empty state.

### Spirit Menu
- **What Happens**: Use a Soul-Bound lantern in the air to open a menu with the species, name, health, and variant of the trapped soul.

### Spectral Ally
- **What Happens**: The menu can project a light-blue, slightly transparent spirit for 20 seconds, with a tiny figure of the trapped mob inside. It wanders near you and fights nearby hostile mobs like a pet, never attacks you, then fades back into the lantern, with a 60-second cooldown.

### Mob-Specific Attacks
- **What Happens**: A trapped Creeper becomes a kamikaze that explodes beside its target, a Skeleton fires arrows, and a Snow Golem throws snowballs. Spiders, wolves, and chickens attack fast, while Iron Golems and Endermen hit hard.

### Rename Captured Mob
- **What Happens**: Give the trapped creature a custom name from the menu without using a Name Tag.

## How to Use

1. Craft a Soul Lantern at a crafting table.
2. Hold the Soul Lantern, sneak, and interact with a mob to seal it.
3. Use the Soul-Bound lantern in the air to open the Spirit menu.
4. Choose Project Spectral Ally to summon a temporary helper, or Rename Captured Mob to rename the soul.
5. Interact with a block while holding the Soul-Bound lantern to release the mob on top of it.
