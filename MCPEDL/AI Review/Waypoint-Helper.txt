### 1.3 Version Format and Manifests
**Manifest versioning (Bedrock engine format):** `header.version` MUST be a 3-integer array `[X, Y, Z]` (e.g. `[1, 0, 0]`, `[2, 0, 0]`); `metadata.version` MUST be the string `"X.Y.Z"` (e.g. `"1.0.0"`). The Bedrock engine rejects non-array values or strings like `"vX"` in manifests. NEVER use `vX` syntax inside any `manifest.json` field.
**Per-pack user-facing format:** Every user-visible reference to a version uses `vX` (a single whole number): pack title suffix `(vX)`, changelog headings `## [vX]`, package filenames `(Shortcut VX.ext)`, README download links, CurseForge/MCPEDL release names, snapshot folder prefix `V`. The two formats are strictly separate: manifests = `[X, 0, 0]` / `"X.0.0"`, everything the user sees = `vX`.
- Version = `vX` format (single whole number, e.g. `v2`, `v3`; Bedrock `header.version` maps to `[X, 0, 0]`; legacy `X.Y.Z` supported). NEVER `X.Y.Z.A`. No fourth part, no Alpha. Same version in `metadata.version`, `(vX)` titles, changelog headings, package names, README links, snapshots.

- Update: X+1 (v1 -> v2, v2 -> v3; legacy 1.2.3 converts to v2). Manifest title suffix equals version (e.g. `(v2)`).
- Manifest title = `Add-on Name (vX)` (e.g. `Vanilla Quality of Life (v2)`). Exactly one terminal suffix, equals `header.version` (or major integer), BP/RP match. NEVER duplicate suffixes. `scripts/validate_manifest_titles.py [--project <path>]` fails the job on violation (also notes non-fail: format_version != 2, missing/zero `min_engine_version`, missing `metadata.authors`).

- `header.description` contains `by ALNStudios` exactly once. NEVER attribution in title.
- NEVER change pack UUIDs or world storage keys to rename a title. NEVER regenerate header UUIDs (breaks worlds).
- Build sync: every processed project aligns all source manifests to one highest `X.Y.Z`: `header.version`, `metadata.version`, title suffix, module versions, same-project BP/RP deps. FORCES `metadata.authors` = `["ALNStudios"]` and `metadata.product_type` = `"addon"` in EVERY BP and RP manifest (new packs, updates, builds; NEVER another author or type), optional `metadata.license`. `product_type` `"addon"` is what keeps achievements allowed (owner-confirmed in game). ### 1.12 Vanilla Limits and Workarounds
Applies to every addon, map, script, minigame, item, entity, block, trade, recipe and enchantment, new or updated.
- A hardcoded vanilla limit blocks the requested mechanic (examples: mutually exclusive enchantments, item, entity or component caps, trade or recipe limits) AND the standard approach (behavior JSON, commands, crafting, enchanting) fails: NEVER drop the feature silently. The standard approach works: use it, no workaround.
- Lightest workaround first. 1) Data-driven: custom item, block, entity, recipe, loot, trade, spawn rule, animation controller, tag, component. 2) `@minecraft/server`: custom components, events, ItemStack and Entity APIs, dynamic properties, tags or scoreboard for state. 3) Structural: helper or proxy entity, swapped or replaced item or entity, tiered item variants, `.mcstructure` or template placement, function-driven effects.
- NEVER invent an API, component, event or behavior. Use only what the looked-up stable version (1.2) provides and the repo scripts accept. Cannot verify: say so in DESCRIPTION.md.
- Modular: one small file per workaround with one entry point (script: `behavior_pack/scripts/lib/<name>.js` imported relatively; data: its own function file, entity or item definition). Reuse an existing module. NEVER copy the logic per feature.
- Safe: idempotent setup, caps and cleanup for spawned entities and loops, nothing that corrupts worlds or other packs.
- Conflict Prevention & Isolation:
  1. Custom namespace isolation: Always prefix custom items, blocks, and entities with `aln:<name>` (e.g. `aln:<minigame_name>_controller`).
  2. Avoid Vanilla Entity Overrides: Overriding vanilla entity JSON files (e.g. `entities/zombie.json`) completely wipes out other addons modifying the same entity in Bedrock's load order. Whenever possible, hook into vanilla entity mechanics using `@minecraft/server` Script API event subscriptions (`world.afterEvents.entityDie`, `playerInteractWithEntity`, `entityHurt`, etc.) rather than replacing the vanilla entity JSON.
- Docs (`DOCS_RULES.md`): player-facing result only, no code or API names; the trade-off under Good To Know. State achievement and experiment impact per 1.2.

### 1.16 Bedrock Developer Role and Trusted Sources
- Role: expert Minecraft Bedrock Add-on and Script API developer. Build and maintain complete Behavior Packs, Resource Packs and Script API modules. Recipes reference vanilla item identifiers directly. NEVER duplicate vanilla PNGs unless needed as templates.
- Trusted sources (rely strictly and exclusively on these four Context7 libraries, queried per 1.17; NEVER invent API methods, outdated syntax or item ids): `/microsoftdocs/minecraft-creator` (Script API, `@minecraft/server`, `@minecraft/server-ui`, JSON schemas, versions); `/mojang/bedrock-samples` (vanilla textures, recipes, entities, definitions, formats); `/websites/wiki_bedrock_dev` (manifest structure, techniques); `/allenscreations/mcpe-curseforges` (this repo's rules and scripts). No other library, site or package page is a source. Priority and disagreements follow 1.1: report, NEVER choose silently.

- Output: complete ready-to-use files with exact repo-root-relative paths, delivered ONLY as the single update `.sh` (`<Repofilename>_<Version>_<Rand>.sh`) or the single pack `.sh` (new packs) and reply format above (Reply Format, Termux Script Rules).
- Item/Block menu_category: When defining `menu_category` in custom items or blocks, `group` MUST start with a namespace (e.g. `minecraft:itemGroup.name.<group>` or `<pack_namespace>:itemGroup.name.<group>`). Unnamespaced group strings (such as `itemGroup.name.helmet`) fail Bedrock parsing (`Failed to parse field ' -> description -> menu_category -> group: string must be prefixed with a namespace (eg. namespace:value)'`). ### 1.3 Version Format and Manifests
**Manifest versioning (Bedrock engine format):** `header.version` MUST be a 3-integer array `[X, Y, Z]` (e.g. `[1, 0, 0]`, `[2, 0, 0]`); `metadata.version` MUST be the string `"X.Y.Z"` (e.g. `"1.0.0"`). The Bedrock engine rejects non-array values or strings like `"vX"` in manifests. NEVER use `vX` syntax inside any `manifest.json` field.
**Per-pack user-facing format:** Every user-visible reference to a version uses `vX` (a single whole number): pack title suffix `(vX)`, changelog headings `## [vX]`, package filenames `(Shortcut VX.ext)`, README download links, CurseForge/MCPEDL release names, snapshot folder prefix `V`. The two formats are strictly separate: manifests = `[X, 0, 0]` / `"X.0.0"`, everything the user sees = `vX`.
- Version = `vX` format (single whole number, e.g. `v2`, `v3`; Bedrock `header.version` maps to `[X, 0, 0]`; legacy `X.Y.Z` supported). NEVER `X.Y.Z.A`. No fourth part, no Alpha. Same version in `metadata.version`, `(vX)` titles, changelog headings, package names, README links, snapshots.

- Update: X+1 (v1 -> v2, v2 -> v3; legacy 1.2.3 converts to v2). Manifest title suffix equals version (e.g. `(v2)`).
- Manifest title = `Add-on Name (vX)` (e.g. `Vanilla Quality of Life (v2)`). Exactly one terminal suffix, equals `header.version` (or major integer), BP/RP match. NEVER duplicate suffixes. `scripts/validate_manifest_titles.py [--project <path>]` fails the job on violation (also notes non-fail: format_version != 2, missing/zero `min_engine_version`, missing `metadata.authors`).

### 4.13 Pixel textures (custom item and block art)
- The ONLY way to draw new art: pixel JSON, rendered to PNG by `scripts/pixel_json_to_png.py`. NEVER AI-generated images, NEVER copied or guessed art. A vanilla look = use the real vanilla texture name instead. NEVER for `script` projects (no resource_pack).
- Source: `texture_sources/<any>.json` = array of textures. NEVER inside `resource_pack/`. No comments.
- One texture: `{"name": "shepherds_pie", "size": 64, "palette": {"0": "#00000000", "1": "#3d2817"}, "pixels": [[0, 0, 1, ...], ...]}`
- `name`: lowercase letters, digits, `_`. It is the PNG name, the key in `resource_pack/textures/item_texture.json` and the item's `minecraft:icon`. ALWAYS register it there.
- `size`: 64 standard for richer detail and styling freedom (16, 32 or 128 allowed when requested). `pixels` = exactly `size` rows of exactly `size` palette indexes.
- `palette`: keys are numbers in quotes, `"0"` = `#00000000` (transparent). Values `#RRGGBB` or `#RRGGBBAA`. Every index used MUST exist in the palette. Max 12 colors.
- Optional `folder`: `items` (default), `blocks` or `items/<sub>`. The PNG goes to `resource_pack/textures/<folder>/<name>.png`.
- Style: Minecraft pixel art, clean outlines, depth, light from the top left, no gradients, no blurry anti-aliasing, styled for 64x64 high detail. Recolors share one grid with a different palette.
- RUN `python3 pixel_json_to_png.py build/<Name>` BEFORE `make_pack_script.py` (4.8): it checks every texture, lists every problem together and writes the PNGs. Fix, rerun. NEVER hand-write a PNG or base64.
- Ship the JSON AND the PNGs. The JSON is the source: later changes edit the JSON and rerun the script, NEVER the PNG. `--preview [file]` writes a review sheet outside the project: NEVER ship it.

### 4.14 Custom Sounds
- Audio files cannot travel inside a spec or pack script. A project that needs custom sounds keeps a pure-Python synthesizer at `<project>/sound_sources/make_sounds.py` (reference: `MCPEDL/Addons/ALNSpiritSphere/sound_sources/make_sounds.py`). It writes `.ogg` files into `<project>/resource_pack/sounds/` and needs ffmpeg (Termux: `pkg install ffmpeg`).
- An update that adds sounds uses `@@ create` for `make_sounds.py` and `resource_pack/sounds/sound_definitions.json` (`format_version` 1.14.0, one event per sound, sound paths without extension, category neutral). After the update script runs, the user runs: `python3 <project>/sound_sources/make_sounds.py`, then `git add`, `commit`, `push`.

async function pickSlot(player, mode, notice) {
  while (true) {
    const total = slotCount(player);
    const slots = [];
    for (let i = 0; i < total; i++) slots.push(readSlot(player, i));
    const form = new ActionFormData().title(TITLE).body(heading(PICKER[mode].title, `${notice ? `${notice}\n` : ""}${PICKER[mode].body}`));
    form.button("Exit");
    form.button("Back");
    const death = mode === "load" ? readStored(player, DEATH_KEY) : undefined;
    const offset = mode === "load" ? 3 : 2;
    if (mode === "load") form.button(death ? `${dimensionColor(death.d)}Last Death: ${coordText(death)}\n${dimensionName(death.d)}` : "Last Death: None");
    for (let i = 0; i < total; i++) form.button(slotLabel(slots[i], i));
    let next = total + offset;
    let addIndex = -1;
    if (mode === "save" && slots.every((slot) => slot)) {
      form.button("+ Add Slot");
      addIndex = next++;
    }
    const response = await show(form, player);
    if (!response || response.canceled || response.selection === 0) return { kind: "closed" };
    if (response.selection === 1) return { kind: "back" };
    if (response.selection === addIndex) {
      player.setDynamicProperty(COUNT_KEY, total + 1);
      notice = `Slot ${total + 1} added.`;
      continue;
    }
    if (mode === "load" && response.selection === 2) return { kind: "death" };
    return { kind: "slot", index: response.selection - offset };
  }

async function saveFlow(player) {
  let notice;
  while (true) {
    const pick = await pickSlot(player, "save", notice);
    if (pick.kind !== "slot") return pick.kind;
    const existing = readSlot(player, pick.index);
    if (existing) {
      const confirmed = await confirmOverwrite(player, pick.index, existing);
      if (confirmed === null) return "closed";
      if (!confirmed) {
        notice = undefined;
        continue;
      }
    }
    const rotation = player.getRotation();
    const data = {
      x: Math.round(player.location.x * 100) / 100,
      y: Math.round(player.location.y * 100) / 100,
      z: Math.round(player.location.z * 100) / 100,
      d: player.dimension.id,
      rx: rotation.x,
      ry: rotation.y,
    };
    const nameForm = new ModalFormData().title(TITLE).textField(`§lName Slot ${pick.index + 1}§r\nName (empty shows coordinates)`, "Example: Home");

    if (!nameResponse || nameResponse.canceled) return "closed";

function groundTarget(dimension, x, y, z) {
  const passable = (yy) => {
    const block = dimension.getBlock({ x, y: yy, z });
    return !!block && (block.isAir || (!block.isSolid && !block.isLiquid));
  };
  const holds = (yy) => {
    const block = dimension.getBlock({ x, y: yy, z });
    return !!block && (block.isSolid || block.isLiquid);
  };
  const range = dimension.heightRange;
  if (!passable(y + 1)) {
    const top = Math.min(y + GROUND_SEARCH, range.max - 1);
    for (let yy = y + 2; yy < top; yy++) if (passable(yy) && passable(yy + 1) && holds(yy - 1)) return yy;
    return null;
  }
  if (!passable(y) || holds(y - 1)) return y;
  const bottom = Math.max(y - GROUND_SEARCH, range.min);
  for (let yy = y - 2; yy > bottom; yy--) if (holds(yy)) return yy + 1;
  return null;
}

function arrivalEffect(player) {
  try {
    const { x, y, z } = player.location;
    for (let i = 0; i < ARRIVAL_PARTICLE_COUNT; i++) {
      const angle = Math.random() * Math.PI * 2;
      const radius = Math.random() * 0.8;
      player.dimension.spawnParticle(ARRIVAL_PARTICLE, {
        x: x + Math.cos(angle) * radius,
        y: y + Math.random() * 2,
        z: z + Math.sin(angle) * radius,
      });
    }
  } catch (error) {
    return;
  }
}

function protectFromFall(player) {
  try {
    player.addEffect("slow_falling", FALL_PROTECTION_TICKS, { amplifier: 0, showParticles: false });
  } catch (error) {
    return;
  }

function settleOnGround(player, color, tries = 0) {
  try {
    if (!player.isValid) return;
    const location = player.location;
    const x = Math.floor(location.x);
    const y = Math.floor(location.y);
    const z = Math.floor(location.z);
    const target = groundTarget(player.dimension, x, y, z);
    if (target === null) {
      actionBar(player, "§eNo solid ground found at this waypoint.");
      return;
    }
    if (target === y) return;
    const below = player.dimension.getBlock({ x, y: target - 1, z });
    if (below && below.typeId.includes("lava")) {
      actionBar(player, "§cLava below this waypoint. Staying put.");
      return;
    }
    player.teleport({ x: location.x, y: target, z: location.z });
    arrivalEffect(player);
    actionBar(player, `${color}Landing moved to solid ground.`);
  } catch (error) {
    if (tries < SETTLE_TRIES) system.runTimeout(() => settleOnGround(player, color, tries + 1), SETTLE_DELAY_TICKS);
  }
}

function startTeleport(player, slot, label) {
  if (teleporting.has(player.id)) {
    actionBar(player, "§eYou are already teleporting.");
    return;
  }
  const readyAt = player.getDynamicProperty(COOLDOWN_KEY);
  const left = typeof readyAt === "number" ? readyAt - Date.now() : 0;
  if (left > 0 && left <= TELEPORT_COOLDOWN_MS) {
    actionBar(player, `§eTeleport ready in ${Math.ceil(left / 1000)} seconds.`);
    return;
  }
  const color = dimensionColor(slot.d);
  const start = player.location;
  const startDimension = player.dimension.id;
  let remaining = TELEPORT_SECONDS * 20;
  let shown = -1;
  let handle;
  const finish = () => {
    system.clearRun(handle);
    teleporting.delete(player.id);
  };
  const cancel = (reason) => {
    finish();
    actionBar(player, `§cTeleport cancelled: ${reason}.`);
    playSound(player, TELEPORT_CANCEL_SOUND, 0.8);
  };
  handle = system.runInterval(() => {
    try {
      if (!player.isValid) {
        finish();
        return;
      }
      const here = player.location;
      const dx = here.x - start.x;
      const dy = here.y - start.y;
      const dz = here.z - start.z;
      if (player.dimension.id !== startDimension || dx * dx + dy * dy + dz * dz > TELEPORT_MOVE_LIMIT_SQ) {
        cancel("you moved");
        return;
      }
      if (remaining <= 0) {
        finish();
        if (teleportTo(player, slot)) {
          player.setDynamicProperty(COOLDOWN_KEY, Date.now() + TELEPORT_COOLDOWN_MS);
          protectFromFall(player);
          playSound(player, TELEPORT_ARRIVE_SOUND, 1);
          arrivalEffect(player);
          actionBar(player, `${color}Teleported to ${label}.`);
          settleOnGround(player, color);
        } else {
          actionBar(player, "§cCould not teleport to that waypoint.");
        }
        return;
      }
      const seconds = Math.ceil(remaining / 20);
      if (seconds !== shown) {
        shown = seconds;
        actionBar(player, `${color}Teleporting to ${label} in §l§f${seconds}§r${color}... Stay still.`);
        playSound(player, TELEPORT_TICK_SOUND, 1 + (TELEPORT_SECONDS - seconds) * 0.25);
      }
      remaining -= TELEPORT_STEP_TICKS;
    } catch (error) {
      finish();
    }
  }, TELEPORT_STEP_TICKS);
  teleporting.set(player.id, { cancel });
}

async function loadFlow(player) {
  let notice;
  while (true) {
    const pick = await pickSlot(player, "load", notice);
    if (pick.kind === "death") {
      const death = readStored(player, DEATH_KEY);
      if (!death) {
        notice = "No death location saved yet.";
        continue;
      }
      startTeleport(player, death, "your last death");
      return "done";
    }

    if (!slot) {
      notice = `Slot ${pick.index + 1} is empty.`;
      continue;

    startTeleport(player, slot, slotName(slot, pick.index));
    return "done";
  }
}

async function deleteFlow(player) {
  let notice;
  while (true) {
    const pick = await pickSlot(player, "delete", notice);
    if (pick.kind !== "slot") return pick.kind;
    const slot = readSlot(player, pick.index);
    if (!slot) {
      const removed = pick.index >= BASE_SLOTS ? trimExtraSlots(player) : 0;

      notice = undefined;
      continue;

    const removed = trimExtraSlots(player);
    actionBar(player, `§aDeleted ${slotName(slot, pick.index)}.${removed > 0 ? ` ${removed} empty extra slot${removed === 1 ? "" : "s"} removed.` : ""}`);

  }
