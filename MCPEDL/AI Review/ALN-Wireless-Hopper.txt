### 1.2 Versions and Compatibility
Latest stable:

Engine:
- `min_engine_version` = lowest game version the pack needs. 3-integer array in the manifest form `[1, RELEASE, PATCH]`: game 26.60 = `[1, 26, 60]`, NEVER `[26, 60, 0]` (Minecraft rejects it and caps at the highest released version). Real looked-up value, NEVER `[0,0,0]`. NEVER hardcode a minimum in docs; a documented minimum uses the same form (`1.26.60`).
- Manifest `format_version` = 2. Item/block `format_version` NEVER newer than `min_engine_version`.
- Compatibility line states only a verified minimum. NEVER "or newer" unverified.
- Updating old pack: ALWAYS keep UUIDs, persistent ids, working behavior. Upgrade deps deliberately. Raising `min_engine_version` drops players: say so in CHANGELOG.

Achievements/experiments (every new pack, meaningful update):
- ALWAYS inspect manifests, deps, stable-vs-preview imports, JSON, components, scripts, functions, world settings. Confirm experiment needs against current docs, NEVER keyword match. Stable Script API alone != experiment or achievements disabled.

- Status: EVERY pack (add-on, map, script, minigame) = ALWAYS `Yes, achievement-friendly.` Every manifest carries `metadata.product_type` = `"addon"`, and the owner confirmed in game (ALN Pointer V20 `.mcaddon`) that a pack of that type keeps achievements allowed. Keep any cheat/command/world caveat as a following sentence. NEVER write Likely, Not or Unknown.

- Handoff: achievement status, experiments (none/required name/unknown), evidence, scope.

Implementation:
1. ALWAYS inspect manifest, entry points, imports, structure first.
2. Confirm each API member exists in the chosen stable module version.
3. Prefer event-driven logic. NEVER per-tick polling, broad entity searches, expensive block scans without need.
4. Vanilla JSON components and `.mcfunction` when simpler. Script API when needed.

### 1.3 Version Format and Manifests
**Manifest versioning (Bedrock engine format):** `header.version` MUST be a 3-integer array `[X, Y, Z]` (e.g. `[1, 0, 0]`, `[2, 0, 0]`); `metadata.version` MUST be the string `"X.Y.Z"` (e.g. `"1.0.0"`). The Bedrock engine rejects non-array values or strings like `"vX"` in manifests. NEVER use `vX` syntax inside any `manifest.json` field.
**Per-pack user-facing format:** Every user-visible reference to a version uses `vX` (a single whole number): pack title suffix `(vX)`, changelog headings `## [vX]`, package filenames `(Shortcut VX.ext)`, README download links, CurseForge/MCPEDL release names, snapshot folder prefix `V`. The two formats are strictly separate: manifests = `[X, 0, 0]` / `"X.0.0"`, everything the user sees = `vX`.
- Version = `vX` format (single whole number, e.g. `v2`, `v3`; Bedrock `header.version` maps to `[X, 0, 0]`; legacy `X.Y.Z` supported). NEVER `X.Y.Z.A`. No fourth part, no Alpha. Same version in `metadata.version`, `(vX)` titles, changelog headings, package names, README links, snapshots.

- Update: X+1 (v1 -> v2, v2 -> v3; legacy 1.2.3 converts to v2). Manifest title suffix equals version (e.g. `(v2)`).
- Manifest title = `Add-on Name (vX)` (e.g. `Vanilla Quality of Life (v2)`). Exactly one terminal suffix, equals `header.version` (or major integer), BP/RP match. NEVER duplicate suffixes. `scripts/validate_manifest_titles.py [--project <path>]` fails the job on violation (also notes non-fail: format_version != 2, missing/zero `min_engine_version`, missing `metadata.authors`).

- `header.description` contains `by ALNStudios` exactly once. NEVER attribution in title.
- NEVER change pack UUIDs or world storage keys to rename a title. NEVER regenerate header UUIDs (breaks worlds).
- Build sync: every processed project aligns all source manifests to one highest `X.Y.Z`: `header.version`, `metadata.version`, title suffix, module versions, same-project BP/RP deps. FORCES `metadata.authors` = `["ALNStudios"]` and `metadata.product_type` = `"addon"` in EVERY BP and RP manifest (new packs, updates, builds; NEVER another author or type), optional `metadata.license`. `product_type` `"addon"` is what keeps achievements allowed (owner-confirmed in game). The Bedrock Wiki says Mojang removed this in game 26.50 (MCPE-242529): if a newer game version shows achievements disabled, report it, do not hide it.
- Snapshots: `builds/<pack>/versions/V<X.Y.Z>/` (packages, `source.zip`, `source.sha256`, `build_info.json`). Refreshed when source/packages differ. Last 5 kept.
- NOTHING auto-bumps. The new version is written in CHANGELOG.md AND, in the same update script, into every source manifest with `python3 scripts/manifest_tools.py --project <path> --set vX` (header.version, metadata.version, title suffix, module and dependency versions; UUIDs untouched; never lowers)
, so every update changes the build. Publish to CurseForge uploads the newest changelog version as written and groups every entry since the last publish. The passive build (`Build Changed Packs & Sync Catalogs`) aligns each pack to its highest existing version and rebuilds. `--bump` / `AUTO_BUMP_MANIFEST=true` remain in `scripts/auto_bump_and_build.py` for manual use only.
- Package name: **`(<Shortcut> VX.<ext>)`** (example **`(MiningHelmet V1.mcaddon)`**, or legacy **`(<Shortcut> VX.Y.Z.<ext>)`**). Always format name references in bold with parentheses. Shortcut = short, letters and digits only (NEVER `-`, `_`, spaces, `by ALNStudios`), close to the add-on name, kept in `scripts/pack_shortcuts.json` by project folder (fallback: folder name joined). Custom via `metadata.package_filename` or `PACK_FILENAME_TEMPLATE`; MUST contain `V{version}` and no parenthesis in the file name itself, else the default is used. CurseForge upload copy uses the same name. `python3 scripts/rename_packages.py --check|--apply` renames old packages and repairs references.
- Creator name `ALNStudios`. `python3 scripts/rename_brand.py --apply` migrates old name. NEVER rename lowercase namespaces (`allenscreations:`).
- Tools: `python3 scripts/manifest_tools.py --project <path> --check|--align|--bump` (`--all --check`). `sync_manifest_versions.py`: deps and `min_engine_version` maintenance; set `min_engine_version` by hand after lookup. `sync_project_docs.py` NOT in build: edit DESCRIPTION/CHANGELOG deliberately. `sync_readme_links.py [--check]` repairs README links (runs after every build).
- LOCK: every `MCPEDL/Addons/` project has `LOCK` at root starting `ALNStudios Add-on Lock v1`. Importer creates it, build enforces it. Missing/invalid = release-blocking: report path, NEVER call build-ready. Safeguard only, not encryption.

### 1.12 Vanilla Limits and Workarounds
Applies to every addon, map, script, minigame, item, entity, block, trade, recipe and enchantment, new or updated.
- A hardcoded vanilla limit blocks the requested mechanic (examples: mutually exclusive enchantments, item, entity or component caps, trade or recipe limits) AND the standard approach (behavior JSON, commands, crafting, enchanting) fails: NEVER drop the feature silently. The standard approach works: use it, no workaround.
- Lightest workaround first. 1) Data-driven: custom item, block, entity, recipe, loot, trade, spawn rule, animation controller, tag, component. 2) `@minecraft/server`: custom components, events, ItemStack and Entity APIs, dynamic properties, tags or scoreboard for state. 3) Structural: helper or proxy entity, swapped or replaced item or entity, tiered item variants, `.mcstructure` or template placement, function-driven effects.
- NEVER invent an API, component, event or behavior. Use only what the looked-up stable version (1.2) provides and the repo scripts accept. Cannot verify: say so in DESCRIPTION.md.
- Modular: one small file per workaround with one entry point (script: `behavior_pack/scripts/lib/<name>.js` imported relatively; data: its own function file, entity or item definition). Reuse an existing module. NEVER copy the logic per feature.
- Safe: idempotent setup, caps and cleanup for spawned entities and loops, nothing that corrupts worlds or other packs.
- Conflict Prevention & Isolation:
  1. Custom namespace isolation: Always prefix custom items, blocks, and entities with `aln:<name>` (e.g. `aln:<minigame_name>_controller`).
  2. Avoid Vanilla Entity Overrides: Overriding vanilla entity JSON files (e.g. `entities/zombie.json`) completely wipes out other addons modifying the same entity in Bedrock's load order. Whenever possible, hook into vanilla entity mechanics using `@minecraft/server` Script API event subscriptions (`world.afterEvents.entityDie`, `playerInteractWithEntity`, `entityHurt`, etc.) rather than replacing the vanilla entity JSON.
- Structural NBT & .mcstructure: When a mechanic requires pre-built templates or saved blocks/entities, place `.mcstructure` and `.nbt` files strictly under `behavior_pack/structures/` (or an optional namespace subfolder like `behavior_pack/structures/aln/<name>.mcstructure`). These files must be generated only by code or exported from Bedrock tools (never hand-written arbitrary bytes). Shipped files must contain no comments, obey the 2 MB per-file size cap, and be stated as "not tested in game" until verified in Minecraft.

- Docs (`DOCS_RULES.md`): player-facing result only, no code or API names; the trade-off under Good To Know. State achievement and experiment impact per 1.2.

import { world, Container, ItemStack } from "@minecraft/server";
import { RECEIVER_TYPES } from "./constants.js";
import { dropReceiver, getReceivers, parseKey } from "./registry.js";

export interface Target {
  key: string;
  container: Container;
}

export interface DistributeResult {
  accepted: number;
  remaining: number;
  receivers: number;
  offline: number;
}

type Resolved = { state: "ok"; container: Container } | { state: "stale" } | { state: "offline" };

const cursors = new Map<string, number>();

function resolveContainer(key: string): Resolved {
  const info = parseKey(key);
  if (!info) return { state: "stale" };
  try {
    const block = world.getDimension(info.dimensionId).getBlock({ x: info.x, y: info.y, z: info.z });
    if (!block) return { state: "offline" };
    if (!RECEIVER_TYPES.has(block.typeId)) return { state: "stale" };
    const container = block.getComponent("inventory")?.container;
    if (!container) return { state: "offline" };
    return { state: "ok", container };
  } catch {
    return { state: "offline" };
  }
}

export function resolveTargets(senderKey: string): { targets: Target[]; offline: number } {
  const targets: Target[] = [];
  let offline = 0;
  for (const key of getReceivers(senderKey)) {
    const result = resolveContainer(key);
    if (result.state === "ok") targets.push({ key, container: result.container });
    else if (result.state === "stale") dropReceiver(senderKey, key);
    else offline += 1;
  }
  return { targets, offline };
}

export function distribute(senderKey: string, stack: ItemStack): DistributeResult {
  const { targets, offline } = resolveTargets(senderKey);
  const total = stack.amount;
  if (targets.length === 0) return { accepted: 0, remaining: total, receivers: 0, offline };

  let remaining = total;
  let active = targets.slice();
  const cursor = cursors.get(senderKey) ?? 0;

  while (remaining > 0 && active.length > 0) {
    const count = active.length;
    const base = Math.floor(remaining / count);
    let extra = remaining % count;
    const next: Target[] = [];
    let progress = 0;
    for (let i = 0; i < count; i += 1) {
      const target = active[(cursor + i) % count];
      let share = base;
      if (extra > 0) {
        share += 1;
        extra -= 1;
      }
      if (share <= 0) {
        next.push(target);
        continue;
      }
      const part = stack.clone();
      part.amount = share;
      let rest: ItemStack | undefined;
      try {
        rest = target.container.addItem(part);
      } catch {
        continue;
      }
      const left = rest ? rest.amount : 0;
      const moved = share - left;
      if (moved > 0) {
        progress += moved;
        remaining -= moved;
      }
      if (left === 0) next.push(target);
    }
    active = next;
    if (progress === 0) break;
  }

  cursors.set(senderKey, (cursor + 1) % targets.length);
  return { accepted: total - remaining, remaining, receivers: targets.length, offline };
}

# ALN Wireless Hopper: script notes

Entry point: `scripts/main.ts` (compiled to `main.js`) calls `initRemote()`, `initSenderLoop()` and `initCleanup()` once. Imports used: `@minecraft/server` (manifest dependency 2.11.0) and relative files only. Sources are TypeScript; the `.js` files are generated by the repo compile step.

## Files

- `main.ts`: starts the three modules below.
- `lib/constants.ts`: ids (`minecraft:hopper`, `aln:wireless_remote`, `aln:wireless_remote_linked`), receiver block types, the world dynamic property name, limits (24 receivers per hopper, 64 registered hoppers), the 5-tick send interval, dimension short codes. No dependencies.
- `lib/registry.ts`: stores sender-to-receiver links as one JSON string in a world dynamic property with an in-memory cache. Exports `makeKey`, `blockKey`, `parseKey`, `getReceivers`, `hasLinks`, `linkedHopperKeys`, `isSender`, `isReceiver`, `toggleReceiver`, `dropReceiver`, `dropReceiverEverywhere`, `removeHopper`. Blocks chains: a sender cannot be a receiver and a receiver cannot send. Depends on `constants.ts`.
- `lib/lore.ts`: writes and reads the registered Hopper position in the Linked Wireless Remote's lore. Depends on `registry.ts`.
- `lib/feedback.ts`: action bar messages (green success, yellow warning, red error). No dependencies.
- `lib/distribute.ts`: resolves receiver containers and splits an item stack evenly in rotating order, redistributing what full receivers reject. Skips receivers in unloaded chunks and removes receivers whose block is no longer a Chest, Barrel or Hopper. Depends on `registry.ts`, `constants.ts`.
- `lib/remote.ts`: right-click handling. Remote on a Hopper registers it and becomes the Linked Remote. Linked Remote on a Chest, Barrel or other Hopper links or unlinks it. Linked Remote on its own Hopper turns it back into a blank Remote. Depends on `registry.ts`, `lore.ts`, `feedback.ts`, `constants.ts`.
- `lib/sender_loop.ts`: every 5 ticks, empties each registered Hopper in a loaded chunk into its receivers through `distribute.ts`. Removes a registration when the block is no longer a Hopper. Does nothing when no Hopper is registered. Depends on `distribute.ts`, `registry.ts`, `constants.ts`.
- `lib/cleanup.ts`: breaking a Hopper, Chest or Barrel removes its links. Depends on `registry.ts`, `constants.ts`.

## Ids and events

- Items `aln:wireless_remote` and `aln:wireless_remote_linked`.
- Events: `world.beforeEvents.playerInteractWithBlock`, `world.afterEvents.playerBreakBlock`, `system.runInterval`.
- Dynamic property: world `aln:wh_links`.

## Known limits

- There is no event for items entering a container, so registered Hoppers are checked on a timer.
- A Hopper still pushes items into whatever it faces, which can race with the wireless delivery.
- Receivers in unloaded chunks are skipped.
- Hoppers destroyed by explosions or commands keep their stored links until the position is checked again.
- Both halves of a double chest are separate links.

import { world, Block } from "@minecraft/server";
import { DIM_CODES, MAX_HOPPERS, MAX_RECEIVERS, PROP_LINKS } from "./constants.js";

export interface KeyInfo {
  dimensionId: string;
  x: number;
  y: number;
  z: number;
}

export type ToggleResult = "added" | "removed" | "full" | "limit" | "self" | "chain";

type LinkMap = Record<string, string[]>;

let cache: LinkMap | undefined;

function load(): LinkMap {
  if (cache) return cache;
  let raw: unknown;
  try {
    raw = world.getDynamicProperty(PROP_LINKS);
  } catch {
    raw = undefined;
  }
  let parsed: unknown = {};
  if (typeof raw === "string") {
    try {
      parsed = JSON.parse(raw);
    } catch {
      parsed = {};
    }
  }
  const links: LinkMap = {};
  if (parsed && typeof parsed === "object" && !Array.isArray(parsed)) {
    for (const [key, value] of Object.entries(parsed as Record<string, unknown>)) {
      if (Array.isArray(value)) {
        const list = value.filter((entry): entry is string => typeof entry === "string");
        if (list.length > 0) links[key] = list;
      }
    }
  }
  cache = links;
  return links;
}

function save(): void {
  try {
    world.setDynamicProperty(PROP_LINKS, JSON.stringify(load()));
  } catch {
    return;
  }
}

export function makeKey(dimensionId: string, x: number, y: number, z: number): string {
  const code = DIM_CODES[dimensionId] ?? dimensionId;
  return `${code}|${x}|${y}|${z}`;
}

export function blockKey(block: Block): string {
  const location = block.location;
  return makeKey(block.dimension.id, location.x, location.y, location.z);
}

export function parseKey(key: string): KeyInfo | undefined {
  const parts = key.split("|");
  if (parts.length !== 4) return undefined;
  const entry = Object.entries(DIM_CODES).find(([, code]) => code === parts[0]);
  const dimensionId = entry ? entry[0] : parts[0];
  const x = Number(parts[1]);
  const y = Number(parts[2]);
  const z = Number(parts[3]);
  if (![x, y, z].every(Number.isFinite)) return undefined;
  return { dimensionId, x, y, z };
}

export function getReceivers(senderKey: string): string[] {
  return (load()[senderKey] ?? []).slice();
}

export function hasLinks(): boolean {
  return Object.keys(load()).length > 0;
}

export function linkedHopperKeys(): string[] {
  return Object.keys(load());
}

export function isSender(key: string): boolean {
  return key in load();
}

export function isReceiver(key: string): boolean {
  return Object.values(load()).some((list) => list.includes(key));
}

export function toggleReceiver(senderKey: string, receiverKey: string): ToggleResult {
  const links = load();
  const list = links[senderKey] ?? [];
  const index = list.indexOf(receiverKey);
  if (index >= 0) {
    list.splice(index, 1);
    if (list.length === 0) delete links[senderKey];
    else links[senderKey] = list;
    save();
    return "removed";
  }
  if (receiverKey === senderKey) return "self";
  if (isSender(receiverKey)) return "chain";
  if (list.length === 0 && isReceiver(senderKey)) return "chain";
  if (list.length >= MAX_RECEIVERS) return "full";
  if (!(senderKey in links) && Object.keys(links).length >= MAX_HOPPERS) return "limit";
  list.push(receiverKey);
  links[senderKey] = list;
  save();
  return "added";
}

export function dropReceiver(senderKey: string, receiverKey: string): void {
  const links = load();
  const list = links[senderKey];
  if (!list) return;
  const index = list.indexOf(receiverKey);
  if (index < 0) return;
  list.splice(index, 1);
  if (list.length === 0) delete links[senderKey];
  save();
}

export function dropReceiverEverywhere(receiverKey: string): void {
  for (const senderKey of Object.keys(load())) {
    dropReceiver(senderKey, receiverKey);
  }
}

export function removeHopper(senderKey: string): void {
  const links = load();
  if (!(senderKey in links)) return;
  delete links[senderKey];
  save();
}

import { world, system, Block, Dimension, ItemStack, Player, Vector3 } from "@minecraft/server";
import { HOPPER_TYPE, LINKED_ID, RECEIVER_TYPES, REMOTE_ID } from "./constants.js";
import { notify } from "./feedback.js";
import { decodeSender, encodeSender } from "./lore.js";
import { getReceivers, makeKey, parseKey, removeHopper, toggleReceiver } from "./registry.js";

interface Context {
  player: Player;
  dimension: Dimension;
  loc: Vector3;
}

function safeBlock(dimension: Dimension, loc: Vector3): Block | undefined {
  try {
    return dimension.getBlock(loc);
  } catch {
    return undefined;
  }
}

function setHeld(player: Player, item: ItemStack): void {
  const container = player.getComponent("inventory")?.container;
  if (!container) return;
  container.setItem(player.selectedSlotIndex, item);
}

function blankRemote(): ItemStack {
  return new ItemStack(REMOTE_ID, 1);
}

function register(ctx: Context): void {
  const block = safeBlock(ctx.dimension, ctx.loc);
  if (!block || block.typeId !== HOPPER_TYPE) {
    notify(ctx.player, "That Hopper is gone.", "error");
    return;
  }
  const key = makeKey(ctx.dimension.id, ctx.loc.x, ctx.loc.y, ctx.loc.z);
  const linked = new ItemStack(LINKED_ID, 1);
  linked.setLore(encodeSender(key));
  setHeld(ctx.player, linked);
  const count = getReceivers(key).length;
  notify(ctx.player, `Hopper registered (${count} linked). Right-click containers to link them.`, "ok");
}

function unregister(ctx: Context): void {
  setHeld(ctx.player, blankRemote());
  notify(ctx.player, "Remote cleared. Right-click a Hopper to register it.", "warn");
}

function bind(ctx: Context, senderKey: string): void {
  const info = parseKey(senderKey);
  if (!info) {
    setHeld(ctx.player, blankRemote());
    notify(ctx.player, "This Remote has no valid Hopper. It was cleared.", "error");
    return;
  }
  let senderBlock: Block | undefined;
  try {
    senderBlock = world.getDimension(info.dimensionId).getBlock({ x: info.x, y: info.y, z: info.z });
  } catch {
    senderBlock = undefined;
  }
  if (!senderBlock) {
    notify(ctx.player, "The registered Hopper is not loaded right now.", "warn");
    return;
  }
  if (senderBlock.typeId !== HOPPER_TYPE) {
    removeHopper(senderKey);
    setHeld(ctx.player, blankRemote());
    notify(ctx.player, "The registered Hopper no longer exists. Remote cleared.", "error");
    return;
  }
  const target = safeBlock(ctx.dimension, ctx.loc);
  if (!target || !RECEIVER_TYPES.has(target.typeId)) {
    notify(ctx.player, "That is not a Chest, Barrel or Hopper.", "error");
    return;
  }
  const result = toggleReceiver(senderKey, makeKey(ctx.dimension.id, ctx.loc.x, ctx.loc.y, ctx.loc.z));
  const count = getReceivers(senderKey).length;
  switch (result) {
    case "added":
      notify(ctx.player, `Receiver linked (${count} total).`, "ok");
      break;
    case "removed":
      notify(ctx.player, `Receiver unlinked (${count} total).`, "warn");
      break;
    case "full":
      notify(ctx.player, "This Hopper has the maximum number of receivers.", "error");
      break;
    case "limit":
      notify(ctx.player, "The world has the maximum number of registered Hoppers.", "error");
      break;
    case "self":
      notify(ctx.player, "A Hopper cannot be its own receiver.", "error");
      break;
    default:
      notify(ctx.player, "A sending Hopper cannot be a receiver, and a receiver cannot send.", "error");
      break;
  }
}

export function initRemote(): void {
  world.beforeEvents.playerInteractWithBlock.subscribe((event) => {
    if (!event.isFirstEvent) return;
    const held = event.itemStack;
    if (!held) return;
    const isBlank = held.typeId === REMOTE_ID;
    const isLinked = held.typeId === LINKED_ID;
    if (!isBlank && !isLinked) return;
    const block = event.block;
    const typeId = block.typeId;
    if (!RECEIVER_TYPES.has(typeId)) return;

    const player = event.player;
    const dimension = block.dimension;
    const loc: Vector3 = { x: block.location.x, y: block.location.y, z: block.location.z };
    const ctx: Context = { player, dimension, loc };
    const isHopper = typeId === HOPPER_TYPE;
    const senderKey = isLinked ? decodeSender(held.getLore()) : undefined;

    event.cancel = true;

    if (!senderKey) {
      if (isHopper) system.run(() => register(ctx));
      else system.run(() => notify(player, "Right-click a Hopper with the Remote first.", "warn"));
      return;
    }

    const key = makeKey(dimension.id, loc.x, loc.y, loc.z);
    if (isHopper && key === senderKey) system.run(() => unregister(ctx));
    else system.run(() => bind(ctx, senderKey));
  });
}

import { world, system, Block } from "@minecraft/server";
import { HOPPER_TYPE, SEND_INTERVAL } from "./constants.js";
import { distribute } from "./distribute.js";
import { hasLinks, linkedHopperKeys, parseKey, removeHopper } from "./registry.js";

function drain(senderKey: string): void {
  const info = parseKey(senderKey);
  if (!info) {
    removeHopper(senderKey);
    return;
  }
  let block: Block | undefined;
  try {
    block = world.getDimension(info.dimensionId).getBlock({ x: info.x, y: info.y, z: info.z });
  } catch {
    return;
  }
  if (!block) return;
  if (block.typeId !== HOPPER_TYPE) {
    removeHopper(senderKey);
    return;
  }
  const container = block.getComponent("inventory")?.container;
  if (!container) return;
  for (let slot = 0; slot < container.size; slot += 1) {
    const item = container.getItem(slot);
    if (!item) continue;
    const result = distribute(senderKey, item);
    if (result.receivers === 0) return;
    if (result.accepted === 0) continue;
    if (result.remaining > 0) {
      item.amount = result.remaining;
      container.setItem(slot, item);
    } else {
      container.setItem(slot, undefined);
    }
  }
}

export function initSenderLoop(): void {
  system.runInterval(() => {
    if (!hasLinks()) return;
    for (const senderKey of linkedHopperKeys()) {
      try {
        drain(senderKey);
      } catch {
        continue;
      }
    }
  }, SEND_INTERVAL);
}

# ALN Wireless Hopper — Remote-Linked Item Delivery

**By ALNStudios**

[![Minecraft Bedrock](https://img.shields.io/badge/Minecraft%20Bedrock-Stable%20Release-brightgreen?style=flat-square&logo=minecraft)](https://github.com/AllensCreations/MCPE-Curseforges)

**Register any Hopper with the Wireless Remote, then link up to 24 Chests, Barrels or Hoppers to receive everything it takes in.**

> This pack adds the Wireless Remote and the Linked Wireless Remote. A normal Hopper becomes a wireless sender, and its items are shared out to every container you link, with no menus.

## Overview

You craft a Wireless Remote and right-click a Hopper with it. The Remote turns into a Linked Wireless Remote with its own texture and shows which Hopper it controls. Use the Linked Remote on Chests, Barrels and other Hoppers to link them. Anything the registered Hopper takes in is then split evenly across your linked containers, wherever they are.

## Key Features

### Wireless Remote
- **What Happens**: A handheld tool that registers a Hopper. Right-click any Hopper and the Remote becomes a Linked Wireless Remote for that Hopper.
- **How It Works**: The Linked Remote's tooltip shows the Hopper's coordinates and dimension, so you can see which Hopper it controls.
- **Good To Know**: Right-click the registered Hopper again with its Linked Remote to turn it back into a blank Remote and register a different Hopper. The Hopper keeps its links.

### Linked Wireless Remote
- **What Happens**: Links containers to the registered Hopper with a right-click and no menu.
- **How It Works**: Right-click a Chest, Barrel or Hopper to link it. Right-click a linked one again to unlink it.
- **Good To Know**: Each registered Hopper holds up to 24 links. Linking does not open the container.

### Wireless Delivery
- **What Happens**: Items that enter a registered Hopper are moved out to the linked containers about four times per second.
- **How It Works**: Feed the Hopper the normal way: from a Hopper above it, from a dropper, or by dropping items on it.
- **Good To Know**: The Hopper still pushes items into whatever it faces. Point it at a wall or empty space if you want every item delivered wirelessly.

### Even Distribution
- **What Happens**: Each stack is divided evenly across all linked containers, one after another in rotation.
- **How It Works**: If a container is full, its share goes to the others. Items nobody can take stay in the Hopper.
- **Good To Know**: Containers in unloaded areas are skipped until you are nearby again. A sending Hopper cannot be a receiver, and a Hopper cannot be its own receiver.

### Crafting
- **What Happens**: The Wireless Remote is craftable at a crafting table and unlocked from the start.
- **How It Works**: Copper Ingot, 2 Iron Ingots, Ender Pearl and Redstone. Place them as the recipe book shows.
- **Good To Know**: The Linked Wireless Remote is not crafted. You make it by registering a Hopper.

## How to Use

1. Craft a Wireless Remote and place a Hopper.
2. Right-click the Hopper with the Remote. The Remote changes texture and the action bar confirms it.
3. Right-click each Chest, Barrel or Hopper you want to link with the Linked Remote.
4. Put items into the registered Hopper. They are delivered to every linked container.

## Common Questions

- **Can a Hopper be a receiver?**: Yes. Right-click it with a Linked Remote. A Hopper that sends cannot also receive.
- **How do I register a different Hopper?**: Right-click the registered Hopper with its Linked Remote to get a blank Remote back.
