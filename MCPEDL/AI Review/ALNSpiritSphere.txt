### 1.3 Version Format and Manifests
**Manifest versioning (Bedrock engine format):** `header.version` MUST be a 3-integer array `[X, Y, Z]` (e.g. `[1, 0, 0]`, `[2, 0, 0]`); `metadata.version` MUST be the string `"X.Y.Z"` (e.g. `"1.0.0"`). The Bedrock engine rejects non-array values or strings like `"vX"` in manifests. NEVER use `vX` syntax inside any `manifest.json` field.
**Per-pack user-facing format:** Every user-visible reference to a version uses `vX` (a single whole number): pack title suffix `(vX)`, changelog headings `## [vX]`, package filenames `(Shortcut VX.ext)`, README download links, CurseForge/MCPEDL release names, snapshot folder prefix `V`. The two formats are strictly separate: manifests = `[X, 0, 0]` / `"X.0.0"`, everything the user sees = `vX`.
- Version = `vX` format (single whole number, e.g. `v2`, `v3`; Bedrock `header.version` maps to `[X, 0, 0]`; legacy `X.Y.Z` supported). NEVER `X.Y.Z.A`. No fourth part, no Alpha. Same version in `metadata.version`, `(vX)` titles, changelog headings, package names, README links, snapshots.

- Update: X+1 (v1 -> v2, v2 -> v3; legacy 1.2.3 converts to v2). Manifest title suffix equals version (e.g. `(v2)`).
- Manifest title = `Add-on Name (vX)` (e.g. `Vanilla Quality of Life (v2)`). Exactly one terminal suffix, equals `header.version` (or major integer), BP/RP match. NEVER duplicate suffixes. `scripts/validate_manifest_titles.py [--project <path>]` fails the job on violation (also notes non-fail: format_version != 2, missing/zero `min_engine_version`, missing `metadata.authors`).

- `header.description` contains `by ALNStudios` exactly once. NEVER attribution in title.
- NEVER change pack UUIDs or world storage keys to rename a title. NEVER regenerate header UUIDs (breaks worlds).
- Build sync: every processed project aligns all source manifests to one highest `X.Y.Z`: `header.version`, `metadata.version`, title suffix, module versions, same-project BP/RP deps. FORCES `metadata.authors` = `["ALNStudios"]` and `metadata.product_type` = `"addon"` in EVERY BP and RP manifest (new packs, updates, builds; NEVER another author or type), optional `metadata.license`. `product_type` `"addon"` is what keeps achievements allowed (owner-confirmed in game). The Bedrock Wiki says Mojang removed this in game 26.50 (MCPE-242529): if a newer game version shows achievements disabled, report it, do not hide it.
- Snapshots: `builds/<pack>/versions/V<X.Y.Z>/` (packages, `source.zip`, `source.sha256`, `build_info.json`). Refreshed when source/packages differ. Last 5 kept.
- NOTHING auto-bumps. The new version is written in CHANGELOG.md AND, in the same update script, into every source manifest with `python3 scripts/manifest_tools.py --project <path> --set vX` (header.version, metadata.version, title suffix, module and dependency versions; UUIDs untouched; never lowers)
, so every update changes the build. Publish to CurseForge uploads the newest changelog version as written and groups every entry since the last publish. The passive build (`Build Changed Packs & Sync Catalogs`) aligns each pack to its highest existing version and rebuilds. `--bump` / `AUTO_BUMP_MANIFEST=true` remain in `scripts/auto_bump_and_build.py` for manual use only.
- Package name: **`(<Shortcut> VX.<ext>)`** (example **`(MiningHelmet V1.mcaddon)`**, or legacy **`(<Shortcut> VX.Y.Z.<ext>)`**). Always format name references in bold with parentheses. Shortcut = short, letters and digits only (NEVER `-`, `_`, spaces, `by ALNStudios`), close to the add-on name, kept in `scripts/pack_shortcuts.json` by project folder (fallback: folder name joined). Custom via `metadata.package_filename` or `PACK_FILENAME_TEMPLATE`; MUST contain `V{version}` and no parenthesis in the file name itself, else the default is used. CurseForge upload copy uses the same name. `python3 scripts/rename_packages.py --check|--apply` renames old packages and repairs references.
- Creator name `ALNStudios`. `python3 scripts/rename_brand.py --apply` migrates old name. NEVER rename lowercase namespaces (`allenscreations:`).
- Tools: `python3 scripts/manifest_tools.py --project <path> --check|--align|--bump` (`--all --check`). `sync_manifest_versions.py`: deps and `min_engine_version` maintenance; set `min_engine_version` by hand after lookup. `sync_project_docs.py` NOT in build: edit DESCRIPTION/CHANGELOG deliberately. `sync_readme_links.py [--check]` repairs README links (runs after every build).
- LOCK: every `MCPEDL/Addons/` project has `LOCK` at root starting `ALNStudios Add-on Lock v1`. Importer creates it, build enforces it. Missing/invalid = release-blocking: report path, NEVER call build-ready. Safeguard only, not encryption.

### 1.12 Vanilla Limits and Workarounds
Applies to every addon, map, script, minigame, item, entity, block, trade, recipe and enchantment, new or updated.
- A hardcoded vanilla limit blocks the requested mechanic (examples: mutually exclusive enchantments, item, entity or component caps, trade or recipe limits) AND the standard approach (behavior JSON, commands, crafting, enchanting) fails: NEVER drop the feature silently. The standard approach works: use it, no workaround.
- Lightest workaround first. 1) Data-driven: custom item, block, entity, recipe, loot, trade, spawn rule, animation controller, tag, component. 2) `@minecraft/server`: custom components, events, ItemStack and Entity APIs, dynamic properties, tags or scoreboard for state. 3) Structural: helper or proxy entity, swapped or replaced item or entity, tiered item variants, `.mcstructure` or template placement, function-driven effects.
- NEVER invent an API, component, event or behavior. Use only what the looked-up stable version (1.2) provides and the repo scripts accept. Cannot verify: say so in DESCRIPTION.md.
- Modular: one small file per workaround with one entry point (script: `behavior_pack/scripts/lib/<name>.js` imported relatively; data: its own function file, entity or item definition). Reuse an existing module. NEVER copy the logic per feature.
- Safe: idempotent setup, caps and cleanup for spawned entities and loops, nothing that corrupts worlds or other packs.
- Conflict Prevention & Isolation:
  1. Custom namespace isolation: Always prefix custom items, blocks, and entities with `aln:<name>` (e.g. `aln:<minigame_name>_controller`).
  2. Avoid Vanilla Entity Overrides: Overriding vanilla entity JSON files (e.g. `entities/zombie.json`) completely wipes out other addons modifying the same entity in Bedrock's load order. Whenever possible, hook into vanilla entity mechanics using `@minecraft/server` Script API event subscriptions (`world.afterEvents.entityDie`, `playerInteractWithEntity`, `entityHurt`, etc.) rather than replacing the vanilla entity JSON.
- Docs (`DOCS_RULES.md`): player-facing result only, no code or API names; the trade-off under Good To Know. State achievement and experiment impact per 1.2.

### 1.3 Version Format and Manifests
**Manifest versioning (Bedrock engine format):** `header.version` MUST be a 3-integer array `[X, Y, Z]` (e.g. `[1, 0, 0]`, `[2, 0, 0]`); `metadata.version` MUST be the string `"X.Y.Z"` (e.g. `"1.0.0"`). The Bedrock engine rejects non-array values or strings like `"vX"` in manifests. NEVER use `vX` syntax inside any `manifest.json` field.
**Per-pack user-facing format:** Every user-visible reference to a version uses `vX` (a single whole number): pack title suffix `(vX)`, changelog headings `## [vX]`, package filenames `(Shortcut VX.ext)`, README download links, CurseForge/MCPEDL release names, snapshot folder prefix `V`. The two formats are strictly separate: manifests = `[X, 0, 0]` / `"X.0.0"`, everything the user sees = `vX`.
- Version = `vX` format (single whole number, e.g. `v2`, `v3`; Bedrock `header.version` maps to `[X, 0, 0]`; legacy `X.Y.Z` supported). NEVER `X.Y.Z.A`. No fourth part, no Alpha. Same version in `metadata.version`, `(vX)` titles, changelog headings, package names, README links, snapshots.

- Update: X+1 (v1 -> v2, v2 -> v3; legacy 1.2.3 converts to v2). Manifest title suffix equals version (e.g. `(v2)`).
- Manifest title = `Add-on Name (vX)` (e.g. `Vanilla Quality of Life (v2)`). Exactly one terminal suffix, equals `header.version` (or major integer), BP/RP match. NEVER duplicate suffixes. `scripts/validate_manifest_titles.py [--project <path>]` fails the job on violation (also notes non-fail: format_version != 2, missing/zero `min_engine_version`, missing `metadata.authors`).

- `header.description` contains `by ALNStudios` exactly once. NEVER attribution in title.
- NEVER change pack UUIDs or world storage keys to rename a title. NEVER regenerate header UUIDs (breaks worlds).
- Build sync: every processed project aligns all source manifests to one highest `X.Y.Z`: `header.version`, `metadata.version`, title suffix, module versions, same-project BP/RP deps. FORCES `metadata.authors` = `["ALNStudios"]` and `metadata.product_type` = `"addon"` in EVERY BP and RP manifest (new packs, updates, builds; NEVER another author or type), optional `metadata.license`. `product_type` `"addon"` is what keeps achievements allowed (owner-confirmed in game). The Bedrock Wiki says Mojang removed this in game 26.50 (MCPE-242529): if a newer game version shows achievements disabled, report it, do not hide it.
- Snapshots: `builds/<pack>/versions/V<X.Y.Z>/` (packages, `source.zip`, `source.sha256`, `build_info.json`). Refreshed when source/packages differ. Last 5 kept.

### 4.13 Pixel textures (custom item and block art)
- The ONLY way to draw new art: pixel JSON, rendered to PNG by `scripts/pixel_json_to_png.py`. NEVER AI-generated images, NEVER copied or guessed art. A vanilla look = use the real vanilla texture name instead. NEVER for `script` projects (no resource_pack).
- Source: `texture_sources/<any>.json` = array of textures. NEVER inside `resource_pack/`. No comments.
- One texture: `{"name": "shepherds_pie", "size": 64, "palette": {"0": "#00000000", "1": "#3d2817"}, "pixels": [[0, 0, 1, ...], ...]}`
- `name`: lowercase letters, digits, `_`. It is the PNG name, the key in `resource_pack/textures/item_texture.json` and the item's `minecraft:icon`. ALWAYS register it there.
- `size`: 64 standard for richer detail and styling freedom (16, 32 or 128 allowed when requested). `pixels` = exactly `size` rows of exactly `size` palette indexes.
- `palette`: keys are numbers in quotes, `"0"` = `#00000000` (transparent). Values `#RRGGBB` or `#RRGGBBAA`. Every index used MUST exist in the palette. Max 12 colors.
- Optional `folder`: `items` (default), `blocks` or `items/<sub>`. The PNG goes to `resource_pack/textures/<folder>/<name>.png`.
- Style: Minecraft pixel art, clean outlines, depth, light from the top left, no gradients, no blurry anti-aliasing, styled for 64x64 high detail. Recolors share one grid with a different palette.
- RUN `python3 pixel_json_to_png.py build/<Name>` BEFORE `make_pack_script.py` (4.8): it checks every texture, lists every problem together and writes the PNGs. Fix, rerun. NEVER hand-write a PNG or base64.
- Ship the JSON AND the PNGs. The JSON is the source: later changes edit the JSON and rerun the script, NEVER the PNG. `--preview [file]` writes a review sheet outside the project: NEVER ship it.

### 4.14 Custom Sounds

It writes `.ogg` files into `<project>/resource_pack/sounds/` and needs ffmpeg (Termux: `pkg install ffmpeg`).
- An update that adds sounds uses `@@ create` for `make_sounds.py` and `resource_pack/sounds/sound_definitions.json` (`format_version` 1.14.0, one event per sound, sound paths without extension, category neutral). After the update script runs, the user runs: `python3 <project>/sound_sources/make_sounds.py`, then `git add`, `commit`, `push`.

- An id valid elsewhere may not exist in Bedrock (`oak_door` = `wooden_door`). Confirm id appears in Samples recipes/loot tables/trades before documenting.
- Custom items use the add-on's own RP textures. Vanilla `behavior_pack/recipes/` = reference for recipe format, group tags, ingredient ids.
- Context7 first (1.16). Library empty or asset absent: report. Only GitHub reachable: `git clone --filter=blob:none --sparse` then `git sparse-checkout set --no-cone <paths>`.
- Scale 16x16 textures with nearest-neighbor (`Image.Resampling.NEAREST`).

import { powerOf } from "./elements.js";

const ZOOM_FOV = [70, 62, 50, 38, 46];

export function applyZoom(entry, phase) {
  if (entry.zoom === phase) return;
  entry.zoom = phase;
  try {
    entry.player.runCommand(`camera @s fov_set ${ZOOM_FOV[phase]} 0.35 linear`);
  } catch (e) {}
}

export function clearZoom(player) {
  try {
    player.runCommand("camera @s fov_clear 0.2 linear");
  } catch (e) {}
}

export function chargeSound(player, held, mode) {
  if (held < 2 || held % 3 !== 0) return;
  const k = powerOf(held);
  try {
    player.playSound(`${mode.sfx}.charge`, { pitch: 0.6 + 1.4 * k, volume: 0.5 + 0.4 * k });
  } catch (e) {}
}

    puff(dimension, MID, palm, color);
    for (let f = 0; f < 4; f++) {
      const rise = -0.12 + f * 0.1;
      for (let j = 1; j <= 3; j++) {
        const t = j / 3;
        puff(dimension, SMALL, at(side * spread * (1 - 0.45 * t), rise, -0.12 + 0.24 * t), color);
      }
    }
    const shoulder = { x: loc.x + right.x * side * 0.38, y: loc.y + 1.3, z: loc.z + right.z * side * 0.38 };
    for (let j = 1; j <= 5; j++) {
      const t = j / 6;
      puff(
        dimension,
        SMALL,
        {
          x: shoulder.x + (palm.x - shoulder.x) * t,
          y: shoulder.y + (palm.y - shoulder.y) * t,
          z: shoulder.z + (palm.z - shoulder.z) * t,
        },
        color
      );
    }
  }
}

export function renderCharge(player, held, mode) {
  const dimension = player.dimension;
  const view = player.getViewDirection();
  const center = handPoint(player, view);
  const phase = phaseOf(held);
  if (held % 2 === 0) energyHands(dimension, player, center, view, held, mode.color);
  if (phase === 1) {
    if (held % 2 === 0) ring(dimension, center, view, 0.55, 8, held * 0.25, SMALL, mode.color);
    if (held % 6 === 0) puff(dimension, PULL_HAND, center, mode.color);
  } else if (phase === 2) {
    const k = (held - 24) / (FULL_TICKS - 24);
    ring(dimension, center, view, 0.55 * (1 - k) + 0.04, 6, held * (0.5 + k * 1.5), SMALL, mode.color);
    puff(dimension, MID, center, { red: 1, green: 1, blue: 1 });
    if (held % 2 === 0) puff(dimension, PULL_HAND, center, mode.color);
  } else {
    if (held === BURST_TICK) {
      shell(dimension, center, 0.9, 30, MID, mode.color);
      ring(dimension, center, view, 0.9, 16, 0, BIG, mode.color);
      sound(dimension, `${mode.sfx}.burst`, center);
    }
    puff(dimension, BIG, center, mode.color);
    shell(dimension, center, 0.55 * Math.max(powerOf(held), 0.5), 8, SMALL, mode.color);
    if (phase === 4 && held % 3 === 0) shell(dimension, center, 0.8, 4, MID, { red: 1, green: 1, blue: 1 });
  }
}

export function impactBurst(dimension, center, radius, color) {
  shell(dimension, center, radius * 0.6, 40, MID, color);
  shell(dimension, center, radius * 0.3, 12, BIG, color);
  for (let i = 0; i < 24; i++) {
    const a = (i * Math.PI * 2) / 24;
    puff(dimension, SMALL, { x: center.x + Math.cos(a) * radius, y: center.y + 0.2, z: center.z + Math.sin(a) * radius }, color);
  }
}

export function orbTrail(dimension, center, color, age) {
  puff(dimension, BIG, center, color);
  if (age % 2 === 0) puff(dimension, PULL_ORB, center, color);
  const a = age * 0.9;
  puff(dimension, SMALL, { x: center.x + Math.cos(a) * 0.5, y: center.y + Math.sin(a * 1.3) * 0.5, z: center.z + Math.sin(a) * 0.5 }, color);
  puff(dimension, SMALL, { x: center.x - Math.cos(a) * 0.5, y: center.y - Math.sin(a * 1.3) * 0.5, z: center.z - Math.sin(a) * 0.5 }, color);
}

export function voidSwirl(dimension, center, radius, color, tick) {
  const k = 1 - (tick % 30) / 30;
  const r = radius * k;
  for (let i = 0; i < 8; i++) {
    const a = tick * 0.35 + (i * Math.PI) / 4;
    puff(dimension, SMALL, { x: center.x + Math.cos(a) * r, y: center.y + Math.sin(a * 0.5) * r * 0.4, z: center.z + Math.sin(a) * r }, color);
  }
  puff(dimension, BIG, center, color);
  if (tick % 2 === 0) puff(dimension, PULL_VOID, center, color);
  if (tick > 80) puff(dimension, PULL_CORE, center, color);
}

# ALN:SpiritSphere — Chargeable Elemental Energy Orbs

**By ALNStudios**

[![Minecraft Bedrock](https://img.shields.io/badge/Minecraft%20Bedrock-Stable%20Release-brightgreen?style=flat-square&logo=minecraft)](https://github.com/AllensCreations/MCPE-Curseforges)
[![Format](https://img.shields.io/badge/Format-.MCPACK%20%7C%20.MCADDON%20%7C%20.MCWORLD-blue?style=flat-square)](https://github.com/AllensCreations/MCPE-Curseforges)

**Craft 1 of 10 elemental Spirit Spheres, charge it with a zooming bow-style draw, and fire an orb that peaks at 2.5 seconds.**

> Pick an element, charge its sphere in your hand, and throw an energy orb that behaves like an enhanced Ghast fireball.

## Overview

ALN:SpiritSphere adds ten craftable Spirit Spheres, one per element, that charge like a bow. While you hold use, the view zooms in, a rising tone plays and energy swirls in your hand through three visual phases. On release it launches the Spirit Orb, a projectile whose speed and explosion size depend on how long you charged.

Each sphere has its own color and impact behavior. There is no switching: carry the elements you want and pick them from the hotbar.

## Key Features

### Ten Spirit Spheres
- **What Happens**: Craft the Aero Vortex, Blaze Solar, Frost Nova, Storm Surge, Void Singularity, Terra Quake, Toxic Bloom, Gravity Warp, Life Bloom and Chrono Stasis spheres. Each needs an Ender Pearl, an Amethyst Shard and Blaze Powder plus one element item, in the same order: a Wind Charge or Feather, a Blaze Rod, a Blue Ice, a Lightning Rod, an Obsidian, an Iron Ingot, a Spider Eye, a Phantom Membrane, a Golden Apple or a Clock.

### Hold to Charge
- **What Happens**: Hold use with a sphere like a bow. The longer you hold, the faster the orb flies and the larger its blast.

### Zoom and Charge Sound
- **What Happens**: The view zooms in as the charge passes each of the 3 phases and eases back when you release. A tone rises in pitch while you hold.

### Phase 1: Loose Ring
- **What Happens**: For the first 24 ticks (about 1.2 seconds) a wide ring of energy particles swirls around your hand in the color of the active element.

### Phase 2: Compression
- **What Happens**: From tick 24 the ring tightens and spins faster until it is a dense point of light in your palm.

### Phase 3: Expansion
- **What Happens**: At 50 ticks (2.5 seconds) the core bursts into a large glowing sphere with a sonic pulse. Releasing within the next 0.6 seconds is the sweet spot and gives a 25 percent larger blast.

### Charge-Scaled Orb
- **What Happens**: Releasing fires the Spirit Orb along your aim. A quick release lobs a slow orb with a small blast, a medium charge flies steadily, and a full charge flies almost straight and fast with a cratering explosion.

### Energy Hands
- **What Happens**: While you charge, glowing energy hands made of particles appear on both sides of the sphere, with energy arms running back to your shoulders. The hands close in as the sphere compresses and spread apart when it bursts open.

### Flight Paths
- **What Happens**: Each sphere flies its own way. Aero Vortex corkscrews in a spiral, Blaze Solar flies fast with a slight fireball drop, Frost Nova lobs in a high arc, Storm Surge zigzags side to side, Void Singularity slowly homes in on the nearest mob, Terra Quake flies as a heavy boulder arc, Toxic Bloom wobbles unpredictably, Gravity Warp bends in a wide curve to one side, Life Bloom seeks the nearest other player and Chrono Stasis starts slow and speeds up.

### Sweet Spot and Fading
- **What Happens**: Full power lasts from 50 to 62 ticks. If you keep holding, the sphere shrinks, its tone falls in pitch, and the shot slowly weakens over the next 3 seconds down to 40 percent of its speed and blast. The action bar shows the current power.

### Cooldown
- **What Happens**: After each shot that sphere needs 3 seconds to recharge. Each of the ten spheres has its own cooldown, so you can switch to another element right away.

### Custom Element Sounds
- **What Happens**: Every sphere has its own sounds for charging, the full-charge burst, launch and impact. Aero Vortex sounds like rushing wind, Blaze Solar like crackling fire, Frost Nova like shattering ice, Storm Surge like electric zaps and thunder, Void Singularity like a deep pull and collapse, Terra Quake like crashing rock, Toxic Bloom like bubbling slime, Gravity Warp like warping pulses, Life Bloom like soft chimes and Chrono Stasis like ticking clocks.

### Inward Pull Particles
- **What Happens**: Streams of particles fly inward toward your hand while you charge and toward the orb while it flies. The Void Singularity draws the thickest stream across its full 10 block range and tightens into a dense collapse during its last second.

### Element Colors
- **What Happens**: Each sphere has its own particle color: cyan and white for Aero Vortex, orange and gold for Blaze Solar, icy blue for Frost Nova, purple for Storm Surge, dark magenta for Void Singularity, brown for Terra Quake, toxic green for Toxic Bloom, indigo for Gravity Warp, pink for Life Bloom and teal for Chrono Stasis.

### Element Impacts
- **What Happens**: Aero Vortex adds heavy knockback and a fire-free blast. Blaze Solar ignites the area. Frost Nova freezes nearby water and applies Slowness IV. Storm Surge flies 40 percent faster and calls lightning. Void Singularity stops where it lands, hovers for 5 seconds while it pulls every mob within 10 blocks into its core, then collapses in a larger explosion. Terra Quake digs a wide crater and throws mobs high into the air. Toxic Bloom poisons everything in its cloud. Gravity Warp makes nearby mobs float. Life Bloom gives Regeneration to everything in range instead of damaging it. Chrono Stasis nearly freezes everything it touches in place.

## How to Use

1. Craft a sphere from an Ender Pearl, an Amethyst Shard, Blaze Powder and its element item, such as a Wind Charge or Feather for Aero Vortex or a Clock for Chrono Stasis.
2. Hold use. The view zooms in, a tone rises and the three charge phases build in your hand.
3. Release to fire the orb along your aim. Release early for a slow lob, or release between 50 and 62 ticks for the strongest shot. Holding longer weakens it.
4. Pick another sphere from the hotbar to change the element. The action bar shows the element while you charge.

## FILE: MCPEDL/Addons/ALNSpiritSphere/sound_sources/make_sounds.py (647 lines, 21301 bytes)

import math
import random
import shutil
import struct
import subprocess
import sys
import tempfile
import wave
from pathlib import Path

SR = 22050
TAU = math.pi * 2


def n(sec):
    return int(sec * SR)


def rng_for(name):
    return random.Random(sum(ord(c) * (i + 3) for i, c in enumerate(name)))


def noise(count, rng):
    return [rng.uniform(-1.0, 1.0) for _ in range(count)]


def lp(x, fc):
    out = []
    y = 0.0
    for i, v in enumerate(x):
        f = fc(i / SR) if callable(fc) else fc
        a = 1.0 - math.exp(-TAU * max(f, 5.0) / SR)
        y += a * (v - y)
        out.append(y)
    return out


def hp(x, fc):
    low = lp(x, fc)
    return [a - b for a, b in zip(x, low)]


def bp(x, f_lo, f_hi):
    return lp(hp(x, f_lo), f_hi)


def sweep(count, f0, f1, shape=1.0, wave_fn=None):
    out = []
    phase = 0.0
    for i in range(count):
        t = i / max(count - 1, 1)
        f = f0 + (f1 - f0) * (t ** shape)
        phase = (phase + f / SR) % 1.0
        if wave_fn is None:
            out.append(math.sin(TAU * phase))
        else:
            out.append(wave_fn(phase))
    return out


def saw(p):
    return 2.0 * p - 1.0


def tone(count, freq, wave_fn=None):
    return sweep(count, freq, freq, 1.0, wave_fn)


def env(count, attack, tau, hold=0.0):
    out = []
    a = max(int(attack * SR), 1)
    h = int(hold * SR)
    for i in range(count):
        if i < a:
            out.append(i / a)
        elif i < a + h:
            out.append(1.0)
        else:
            out.append(math.exp(-(i - a - h) / (tau * SR)))
    return out


def swell(count, peak_at):
    out = []
    p = max(int(count * peak_at), 1)
    for i in range(count):
        if i < p:
            out.append((i / p) ** 2)
        else:
            out.append(max(0.0, 1.0 - (i - p) / max(count - p, 1)))
    return out


def reverse_swell(count):
    return [(i / count) ** 3 for i in range(count)]


def mul(x, e):
    return [a * b for a, b in zip(x, e)]


def mix(*parts):
    length = max(len(p[0]) for p in parts)
    out = [0.0] * length
    for samples, gain in parts:
        for i, v in enumerate(samples):
            out[i] += v * gain
    return out


def pad(x, count):
    if len(x) >= count:
        return x[:count]
    return x + [0.0] * (count - len(x))


def delay_line(x, taps):
    length = len(x) + max(int(d * SR) for d, g in taps)
    out = [0.0] * length
    for i, v in enumerate(x):
        out[i] += v
    for d, g in taps:
        o = int(d * SR)
        for i, v in enumerate(x):
            out[i + o] += v * g
    return out


def crackle(count, rng, density, decay):
    out = [0.0] * count
    y = 0.0
    for i in range(count):
        if rng.random() < density:
            y += rng.uniform(-1.0, 1.0)
        y *= decay
        out[i] = y
    return out


def finish(x, peak=0.9):
    m = max(max(abs(v) for v in x), 1e-9)
    x = [v / m * peak for v in x]
    f = int(0.004 * SR)
    for i in range(min(f, len(x))):
        k = i / f
        x[i] *= k
        x[-1 - i] *= k
    return x


def sweep_fc(f0, f1, dur):
    return lambda t: f0 + (f1 - f0) * min(t / dur, 1.0)

def bubbles(c, r, count, f_lo, f_hi, tau, start=0.0, span=1.0):
    out = [0.0] * c
    for _ in range(count):
        s = int((start + r.random() * span) * c)
        f0 = r.uniform(f_lo, f_hi)
        length = min(n(r.uniform(0.04, 0.1)), c - s)
        for i in range(max(length, 0)):
            t = i / SR
            f = f0 * (1.0 + 2.5 * t / 0.08)
            out[s + i] += math.sin(TAU * f * t) * math.exp(-i / (tau * SR))
    return out

def write_wav(path, samples):
    with wave.open(str(path), "wb") as w:
        w.setnchannels(1)
        w.setsampwidth(2)
        w.setframerate(SR)
        w.writeframes(b"".join(struct.pack("<h", int(max(-1.0, min(1.0, v)) * 32767)) for v in samples))


def main():
    if len(sys.argv) > 2:
        print("usage: python3 MCPEDL/Addons/ALNSpiritSphere/sound_sources/make_sounds.py [PROJECT_FOLDER]")
        return 2
    project = Path(sys.argv[1]) if len(sys.argv) == 2 else Path(__file__).resolve().parent.parent
    ffmpeg = shutil.which("ffmpeg")
    if not ffmpeg:
        print("ffmpeg is required to write .ogg files. In Termux run: pkg install ffmpeg")
        return 1
    out_dir = project / "resource_pack" / "sounds" / "aln" / "spirit"
    out_dir.mkdir(parents=True, exist_ok=True)
    with tempfile.TemporaryDirectory() as tmp:
        for name, fn in SOUNDS.items():
            samples = finish(fn(rng_for(name)))
            wav = Path(tmp) / f"{name}.wav"
            write_wav(wav, samples)
            target = out_dir / f"{name}.ogg"
            result = subprocess.run([ffmpeg, "-y", "-loglevel", "error", "-i", str(wav), "-c:a", "libvorbis", "-q:a", "5", str(target)])
            if result.returncode != 0:
                print("ffmpeg failed for", name)
                return 1
            print("wrote", target, f"({len(samples) / SR:.2f}s)")
    print(f"SOUNDS OK: {len(SOUNDS)} file(s)")
    return 0


if __name__ == "__main__":
