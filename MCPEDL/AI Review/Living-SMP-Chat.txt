### 1.3 Version Format and Manifests
**Manifest versioning (Bedrock engine format):** `header.version` MUST be a 3-integer array `[X, Y, Z]` (e.g. `[1, 0, 0]`, `[2, 0, 0]`); `metadata.version` MUST be the string `"X.Y.Z"` (e.g. `"1.0.0"`). The Bedrock engine rejects non-array values or strings like `"vX"` in manifests. NEVER use `vX` syntax inside any `manifest.json` field.
**Per-pack user-facing format:** Every user-visible reference to a version uses `vX` (a single whole number): pack title suffix `(vX)`, changelog headings `## [vX]`, package filenames `(Shortcut VX.ext)`, README download links, CurseForge/MCPEDL release names, snapshot folder prefix `V`. The two formats are strictly separate: manifests = `[X, 0, 0]` / `"X.0.0"`, everything the user sees = `vX`.
- Version = `vX` format (single whole number, e.g. `v2`, `v3`; Bedrock `header.version` maps to `[X, 0, 0]`; legacy `X.Y.Z` supported). NEVER `X.Y.Z.A`. No fourth part, no Alpha. Same version in `metadata.version`, `(vX)` titles, changelog headings, package names, README links, snapshots.

- Update: X+1 (v1 -> v2, v2 -> v3; legacy 1.2.3 converts to v2). Manifest title suffix equals version (e.g. `(v2)`).
- Manifest title = `Add-on Name (vX)` (e.g. `Vanilla Quality of Life (v2)`). Exactly one terminal suffix, equals `header.version` (or major integer), BP/RP match. NEVER duplicate suffixes. `scripts/validate_manifest_titles.py [--project <path>]` fails the job on violation (also notes non-fail: format_version != 2, missing/zero `min_engine_version`, missing `metadata.authors`).

- `header.description` contains `by ALNStudios` exactly once. NEVER attribution in title.
- NEVER change pack UUIDs or world storage keys to rename a title. NEVER regenerate header UUIDs (breaks worlds).

### 1.12 Vanilla Limits and Workarounds
Applies to every addon, map, script, minigame, item, entity, block, trade, recipe and enchantment, new or updated.
- A hardcoded vanilla limit blocks the requested mechanic (examples: mutually exclusive enchantments, item, entity or component caps, trade or recipe limits) AND the standard approach (behavior JSON, commands, crafting, enchanting) fails: NEVER drop the feature silently. The standard approach works: use it, no workaround.
- Lightest workaround first. 1) Data-driven: custom item, block, entity, recipe, loot, trade, spawn rule, animation controller, tag, component. 2) `@minecraft/server`: custom components, events, ItemStack and Entity APIs, dynamic properties, tags or scoreboard for state. 3) Structural: helper or proxy entity, swapped or replaced item or entity, tiered item variants, `.mcstructure` or template placement, function-driven effects.
- NEVER invent an API, component, event or behavior. Use only what the looked-up stable version (1.2) provides and the repo scripts accept. Cannot verify: say so in DESCRIPTION.md.
- Modular: one small file per workaround with one entry point (script: `behavior_pack/scripts/lib/<name>.js` imported relatively; data: its own function file, entity or item definition). Reuse an existing module. NEVER copy the logic per feature.
- Safe: idempotent setup, caps and cleanup for spawned entities and loops, nothing that corrupts worlds or other packs.
- Conflict Prevention & Isolation:
  1. Custom namespace isolation: Always prefix custom items, blocks, and entities with `aln:<name>` (e.g. `aln:<minigame_name>_controller`).
  2. Avoid Vanilla Entity Overrides: Overriding vanilla entity JSON files (e.g. `entities/zombie.json`) completely wipes out other addons modifying the same entity in Bedrock's load order. Whenever possible, hook into vanilla entity mechanics using `@minecraft/server` Script API event subscriptions (`world.afterEvents.entityDie`, `playerInteractWithEntity`, `entityHurt`, etc.) rather than replacing the vanilla entity JSON.
- Docs (`DOCS_RULES.md`): player-facing result only, no code or API names; the trade-off under Good To Know. State achievement and experiment impact per 1.2.

### 1.16 Bedrock Developer Role and Trusted Sources
- Role: expert Minecraft Bedrock Add-on and Script API developer. Build and maintain complete Behavior Packs, Resource Packs and Script API modules. Recipes reference vanilla item identifiers directly. NEVER duplicate vanilla PNGs unless needed as templates.
- Trusted sources (rely strictly and exclusively on these four Context7 libraries, queried per 1.17; NEVER invent API methods, outdated syntax or item ids): `/microsoftdocs/minecraft-creator` (Script API, `@minecraft/server`, `@minecraft/server-ui`, JSON schemas, versions); `/mojang/bedrock-samples` (vanilla textures, recipes, entities, definitions, formats); `/websites/wiki_bedrock_dev` (manifest structure, techniques); `/allenscreations/mcpe-curseforges` (this repo's rules and scripts). No other library, site or package page is a source. Priority and disagreements follow 1.1: report, NEVER choose silently.

- Output: complete ready-to-use files with exact repo-root-relative paths, delivered ONLY as the single update `.sh` (`<Repofilename>_<Version>_<Rand>.sh`) or the single pack `.sh` (new packs) and reply format above (Reply Format, Termux Script Rules).
- Item/Block menu_category: When defining `menu_category` in custom items or blocks, `group` MUST start with a namespace (e.g. `minecraft:itemGroup.name.<group>` or `<pack_namespace>:itemGroup.name.<group>`). Unnamespaced group strings (such as `itemGroup.name.helmet`) fail Bedrock parsing (`Failed to parse field ' -> description -> menu_category -> group: string must be prefixed with a namespace (eg. namespace:value)'`). ### 4.13 Pixel textures (custom item and block art)
- The ONLY way to draw new art: pixel JSON, rendered to PNG by `scripts/pixel_json_to_png.py`. NEVER AI-generated images, NEVER copied or guessed art. A vanilla look = use the real vanilla texture name instead. NEVER for `script` projects (no resource_pack).
- Source: `texture_sources/<any>.json` = array of textures. NEVER inside `resource_pack/`. No comments.
- One texture: `{"name": "shepherds_pie", "size": 64, "palette": {"0": "#00000000", "1": "#3d2817"}, "pixels": [[0, 0, 1, ...], ...]}`
- `name`: lowercase letters, digits, `_`. It is the PNG name, the key in `resource_pack/textures/item_texture.json` and the item's `minecraft:icon`. ALWAYS register it there.
- `size`: 64 standard for richer detail and styling freedom (16, 32 or 128 allowed when requested). `pixels` = exactly `size` rows of exactly `size` palette indexes.
- `palette`: keys are numbers in quotes, `"0"` = `#00000000` (transparent). Values `#RRGGBB` or `#RRGGBBAA`. Every index used MUST exist in the palette. Max 12 colors.
- Optional `folder`: `items` (default), `blocks` or `items/<sub>`. The PNG goes to `resource_pack/textures/<folder>/<name>.png`.
- Style: Minecraft pixel art, clean outlines, depth, light from the top left, no gradients, no blurry anti-aliasing, styled for 64x64 high detail. Recolors share one grid with a different palette.

import { world, system } from "@minecraft/server";
import { ROSTER, formatChat, isOnline, pickOnline } from "./smp_roster.js";
import { REAL_NAMES } from "./smp_voices.js";
import { assembleMessage, pickItem, renderLine } from "./chat_generator.js";
import { DIALOGS, BRAND_DIALOGS } from "./chat_lines_extra.js";
import { WORLD_CHANGES, CHAT_PACE } from "./mode.js";

const MIN_DELAY = 35;
const MAX_DELAY = 100;
const GAP_BETWEEN_CONVERSATIONS = 80;
const MAX_QUEUE = 4;

const queue = [];
let busy = false;

const rand = (a, b) => a + Math.floor(Math.random() * (b - a + 1));

function runNext() {
  if (busy || queue.length === 0) return;
  const lines = queue.shift();
  busy = true;
  let t = rand(20, 50);
  for (const line of lines) {
    system.runTimeout(() => {

      if (line.run) {
        line.run();
        return;
      }
      if (line.bot && !isOnline(line.bot)) return;
      world.sendMessage(line.bot ? formatChat(line.bot, line.text) : line.text);
    }, t);
    t += rand(MIN_DELAY, MAX_DELAY);
  }
  system.runTimeout(() => {
    busy = false;
    runNext();
  }, t + GAP_BETWEEN_CONVERSATIONS);
}

export function playConversation(linesArray, options = {}) {
  const lines = (linesArray || []).filter((l) => l && (l.text || l.run));
  if (lines.length === 0) return false;
  if (options.priority) queue.unshift(lines);
  else if (busy || queue.length > 0) return false;
  else queue.push(lines);
  while (queue.length > MAX_QUEUE) queue.pop();
  runNext();
  return true;
}

function chain(bots, categories, ctx) {
  return bots.map((bot, i) => ({
    bot,
    text: assembleMessage(categories[Math.min(i, categories.length - 1)], { ...ctx, speaker: bot }),
  }));
}

export function reactToDeath(player, kind, cause, hint) {
  const n = rand(2, 4);
  const bots = pickOnline(n);
  if (bots.length < 2) return;
  const first = `death_${kind}`;
  const cats = [first, "death_followup", "support_reply", "death_followup"];
  playConversation(chain(bots, cats, { player, cause, coordHint: hint }), { priority: true });
}

const ORES = {
  "minecraft:diamond_ore": "diamond",
  "minecraft:deepslate_diamond_ore": "diamond",
  "minecraft:ancient_debris": "debris",
};

const EVENT_COOLDOWN = 3600;
const SLEEP_CHANCE = 0.05;
let lastSleepDay = -1;

const rand = (a, b) => a + Math.floor(Math.random() * (b - a + 1));

system.run(() => {
  startSessionSimulator();

function classifyDeath(damageSource) {
  const cause = damageSource ? damageSource.cause : "none";
  const attacker = damageSource ? damageSource.damagingEntity : undefined;
  const typeId = attacker ? attacker.typeId : "";
  const mobName = typeId ? "a " + typeId.replace("minecraft:", "").replace(/_/g, " ") : "a mob";
  if (typeId === "minecraft:creeper" || (cause === "entityExplosion" && !attacker)) return ["creeper", "a creeper"];
  if (cause === "lava") return ["lava", "lava"];
  if (cause === "fall") return ["fall", "fall damage"];
  if (cause === "void") return ["void", "the void"];
  if (attacker && typeId !== "minecraft:player") return ["mob", mobName];
  return ["generic", "something"];
}

world.afterEvents.entityDie.subscribe((ev) => {
  const dead = ev.deadEntity;
  if (!dead || dead.typeId !== "minecraft:player") return;
  try {
    const [kind, cause] = classifyDeath(ev.damageSource);
    const hint = coordHint(dead.location, dead.dimension.id);
    system.runTimeout(() => reactToDeath(dead.name, kind, cause, hint), rand(20, 50));
  } catch (e) {}
});

const oreState = new Map();
world.afterEvents.playerBreakBlock.subscribe((ev) => {
  const kind = ORES[ev.brokenBlockPermutation.type.id];
  if (!kind) return;
  const key = ev.player.id + ":" + kind;
  const now = system.currentTick;
  const st = oreState.get(key);
  if (st && now < st.until) {
    st.count++;
    return;
  }
  const entry = { until: now + ORE_COOLDOWN, count: 1 };
  oreState.set(key, entry);
  const name = ev.player.name;
  const hint = coordHint(ev.player.location, ev.player.dimension.id);

  system.runTimeout(() => reactToOre(name, kind, entry.count, hint), 60);
});

world.afterEvents.playerSpawn.subscribe((ev) => {
  if (!ev.initialSpawn) return;
  const name = ev.player.name;
  system.runTimeout(() => welcomeBack(name), rand(60, 140));
});

const playerState = new Map();
let nextAmbient = rand(1800, 3600) * CHAT_PACE;
let ambientTimer = 0;

system.runInterval(() => {
  ambientTimer += 40;
  const now = system.currentTick;
  const players = world.getAllPlayers();

  try {
    const timeOfDay = world.getTimeOfDay();
    if (timeOfDay >= 13000 && timeOfDay < 23000) {
      const day = world.getDay();
      if (day !== lastSleepDay) {
        lastSleepDay = day;
        if (players.length > 0 && Math.random() < SLEEP_CHANCE) system.runTimeout(() => botSleeps(), rand(100, 2400));
      }
    }
  } catch (e) {}

  for (const p of players) {
    try {
      const dim = p.dimension.id;
      const sleeping = p.isSleeping;
      const st = playerState.get(p.id) || { dim, sleeping: false, last: {} };
      if (dim !== st.dim) {
        const cat = dim === "minecraft:nether" ? "dim_nether" : dim === "minecraft:the_end" ? "dim_end" : null;
        if (cat && now - (st.last[cat] || -EVENT_COOLDOWN) >= EVENT_COOLDOWN) {
          st.last[cat] = now;
          const n = p.name;
          system.runTimeout(() => reactToEvent(n, cat), rand(40, 90));
        }
      }
      if (sleeping && !st.sleeping && now - (st.last.sleep || -EVENT_COOLDOWN) >= EVENT_COOLDOWN) {
        st.last.sleep = now;
        const n = p.name;
        system.runTimeout(() => reactToEvent(n, "sleeping"), rand(30, 70));
      }
      st.dim = dim;
      st.sleeping = sleeping;
      playerState.set(p.id, st);
    } catch (e) {}
  }
  if (oreState.size > 20) {
    for (const [k, v] of oreState) if (now >= v.until) oreState.delete(k);
  }

  if (players.length > 0 && ambientTimer >= nextAmbient) {
    ambientTimer = 0;
    nextAmbient = rand(1800, 3600) * CHAT_PACE;
    ambientConversation();
  }
}, 40);

world.afterEvents.playerLeave.subscribe((ev) => {
  playerState.delete(ev.playerId);
});
try {
  if (world.afterEvents.chatSend) {
    world.afterEvents.chatSend.subscribe((ev) => {
      try {
        replyToChat(ev.sender.name, ev.message);
      } catch (e) {}
    });
  }
} catch (e) {}

**By ALNStudios**

> Living SMP Chat fills the chat with a friendly roster of 40 virtual players who talk to each other and to you. It suits solo worlds that feel too quiet.

## Overview
You play your world as usual. Between 6 and 14 virtual players are online at any time and they join and leave with the normal yellow messages. - **How It Works**: Fall from a high place and one player jokes about the missing water bucket while another offers to meet you at spawn.

### Ore Celebrations
- **What Happens**: Mining Diamond Ore, Deepslate Diamond Ore or Ancient Debris makes virtual players congratulate you.
- **Good To Know**: A whole vein starts one conversation, not one per block. The same ore type will not start another for 1 minute.

### Welcome Back, Sleep and Travel Chat
- **What Happens**: Virtual players greet you when you join, comment when you go to bed, and react when you enter the Nether or the End.
- **Good To Know**: Sleep and travel comments are limited to one every 3 minutes for each kind.

### Ambient Banter
- **What Happens**: Every 1.5 to 3 minutes the virtual players start a 2 to 5 message conversation about weather, farms, trading, raids, bosses, pets, music and more, from short scripted chats to small PvP dramas between three of them.
- **Good To Know**: Conversations are spaced out so replies appear one after another. Overlapping events wait in a short queue instead of flooding the chat.

### Bedtime and Mishaps
- **What Happens**: On about one night in twenty, a virtual player says they are off to bed, others wish them goodnight, and, with the World Changes option, the night then skips to morning. From time to time a virtual player also dies, with the usual death message in chat, and the others react.
- **Good To Know**: Virtual deaths are only chat messages. With World Changes, the night skip does change the time of day for everyone and clears the weather. It never touches your items or position.

### Pack Options
- **What Happens**: The pack offers four options: Just Chat SMP and World Changes, each with a Quiet version. Just Chat SMP keeps everything in chat, World Changes lets the bedtime night skip really change the world, and Quiet makes the virtual players chat about half as often.
- **Good To Know**: Just Chat SMP is the default. Switch options from the pack's settings in your world.


### Replies to Your Chat
- **What Happens**: Virtual players answer when you say hello, thank them, ask a question, laugh, say goodnight, or type one of their names.
- **Good To Know**: They do not answer every message and they wait a few seconds before replying. If your version of Minecraft does not let add-ons read chat, this part simply stays quiet.

### Personalities
- **What Happens**: Each virtual player has a catchphrase, and now and then one of them slips and uses a first name, like a real person typing in the wrong account.
- **Good To Know**: The first names are made up and do not belong to anyone in particular.

### Shoutouts
- **What Happens**: Once in a while a virtual player asks if you know ALNStudios and suggests following him. Some shoutouts are short chats where two or three players talk about who made the add-on.
- **Good To Know**: It happens at most once every 20 minutes.
