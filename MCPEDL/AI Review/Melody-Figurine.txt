# mcpe-pack-update: Update Spec Delivery

## Authority

- `INSTRUCTIONS.md` is the policy source. `PACK_GENERATOR_INSTRUCTIONS.md` is its standalone copy for generation. The script flow is `INSTRUCTIONS.md` "Termux Script Rules", built with `scripts/make_update_script.py`. Where to look each rule up: the `mcpe-context7` skill. ## Scope

- Read-only audit or report: use `checkrm`.
- New project from an idea: follow `PACK_GENERATOR_INSTRUCTIONS.md` Part 4 (ask the type first, base64 payload).

## Procedure

1. Read `INSTRUCTIONS.md` Parts 1 and 2 before writing anything, through Context7 as the `mcpe-context7` skill says. `make_update_script.py` and `apply_update.py` are complete in the pack's review zip (`<Pack>.zip`) under `files/`; run them from there.
2. Find the destination folder: the path the user named, otherwise the matching project folder. Do not substitute a similar name; report ambiguity or a missing target. Ask at most one question, and only if the answer changes gameplay, compatibility, distribution, data loss or versioning.
3. Read the real source (manifests, scripts, items, recipes, loot tables, functions, lang files) before writing any claim. Source priority when sources disagree, and report the disagreement: the project's own files, Mojang Bedrock Samples, official Minecraft Creator Documentation, Minecraft Wiki, Bedrock Wiki.
4. Make the smallest possible change. No unrelated rewrites. Never invent features, versions, links, assets, test results or compatibility. Never write comments in shipped `.js`, `.mcfunction` or `.json` files.
5. Write the spec (below), test it (below), then reply (below). For changes to an existing project, never deliver a .sh: this overrides any older "deliver the .sh" wording. A NEW pack still follows `mcpe-new-pack` and delivers its generated .sh.

## The spec

File name: `spec_vN.txt`, a downloadable file. N = CURRENT VERSION + 1, read from the attached repo export, never guessed. The user builds the .sh on their phone with `scripts/make_update_script.py`.

Format (`scripts/apply_update.py`):

- Start: `@@ version vN`, then `@@ project MCPEDL/<Category>/<Name>`, then one `@@ file <path relative to the project>` block per file.
- Directives: replace/with, replace-all, insert-after, insert-before, delete, append, create, overwrite, changelog. Remove files with `@@ delete-file <repo-root path>`.
- Small change: replace/insert only. Anchors are copied from the attached export, never from memory, and must occur exactly once. Do not end an anchor with a newline.
- Large redesign: `@@ overwrite` (new content must exceed 60% of the old file) or `@@ create` for new files. Never many fragile edits.
- A content line that starts with `@@` is written `@@@`.
- End with `@@ changelog <Update Name>` using `### Added`, `### Improved & Balanced`, `### Fixed` and `- **Title**: text`. Never touch manifest versions or README links.
- New pixel textures: `@@ create` the pixel JSON under `texture_sources/`, then add the PNG step to the Termux commands.
- Keep README.md and DESCRIPTION.md accurate (INSTRUCTIONS Part 2 template). Never claim an in-game test.

**Test before delivering.** Apply the spec to the export text in the sandbox with `apply_update.py` (`--dry-run`, then a real run on a copy). Check every anchor, validate each changed JSON, run `node --check` on JS. Report every check not run.

## Versions

- N is the current version from the attached export plus one. `apply_update.py` rejects a stale version, so a stale spec cannot run on a newer repo.
- Never edit manifest versions or the README version or download link. The auto-version-bump workflow does that on push.

## Docs

- The changelog entry is mandatory on every update and is written with the final `@@ changelog <Update Name>` directive. Never edit or delete older entries; correct them in the new entry.
- After the change, check the README.md and DESCRIPTION.md in the destination. Edit them only if the change makes them inaccurate or incomplete. Never remove verified content.
- Follow the Part 2 templates in `INSTRUCTIONS.md` exactly (`scripts/doc_template.py` fails the build on deviation): same headings, same heading text, same order, same labels, no added sections, no boilerplate, no placeholders. README is version-free and DESCRIPTION has no release version in its title.
- Writing, layout, attribution, keywords and the README and DESCRIPTION templates are defined in `INSTRUCTIONS.md` Part 2. Read them there; do not copy them into the script from memory.

function pulsePlayer(player, step, mode, finale) {
  // Stable camera fades have no alpha/opacity control. Brief, no-hold fades
  // limit how long the color covers the view; this is not a true transparent overlay.
  const pulse = finale ? 2 : (mode === "chill" ? 8 : 4);
  if (step % pulse !== 0) return;

  try {
    player.camera.fade({
      fadeTime: {
        fadeInTime: finale ? 0.06 : (mode === "chill" ? 0.12 : 0.08),
        holdTime: 0,
        fadeOutTime: finale ? 0.2 : (mode === "chill" ? 0.32 : 0.24)

      fadeColor: RAINBOW[Math.floor(step / pulse) % RAINBOW.length]

  } catch {}
}

  // The block model stays still; orbiting particles provide its small animation.
  const speed = mode === "chill" ? 0.28 : mode === "battle" ? 1.05 : 0.72;
  const radius = finale ? 0.42 : 0.28;
  const angle = step * speed;
  const sparkleLocation = {
    x: location.x + Math.cos(angle) * radius,
    y: location.y + 0.55 + Math.sin(angle * 0.8) * (mode === "chill" ? 0.06 : 0.12),
    z: location.z + Math.sin(angle) * radius
  };

  try {
    dimension.spawnParticle("minecraft:note_particle", sparkleLocation);
  } catch {}

  const secondParticleEvery = mode === "chill" ? 4 : 2;
  if (step % secondParticleEvery === 0 || finale && step % 2 === 0) {
    try {
      dimension.spawnParticle("minecraft:enchanting_table_particle", {
        x: location.x + Math.cos(angle + Math.PI) * (finale ? 0.32 : 0.2),
        y: location.y + 0.35 + (finale ? 0.2 : 0),
        z: location.z + Math.sin(angle + Math.PI) * (finale ? 0.32 : 0.2)
      });
    } catch {}
  }

  if (finale && step % 4 === 0) {
    for (let i = 0; i < PARTICLES.length; i++) {
      const burstAngle = angle + (Math.PI * 2 * i) / PARTICLES.length;
      try {
        dimension.spawnParticle(PARTICLES[i], {
          x: location.x + Math.cos(burstAngle) * 0.45,
          y: location.y + 0.45 + (i % 2) * 0.25,
          z: location.z + Math.sin(burstAngle) * 0.45
        });
      } catch {}
    }
  }
}

function rememberRotation(session, entity) {
  try {
    if (!session.originalRotations.has(entity.id)) {
      session.originalRotations.set(entity.id, {
        entity,
        rotation: entity.getRotation()
      });
    }
  } catch {}
}

function restoreMobRotations(session) {
  for (const saved of session.originalRotations.values()) {
    const entity = saved.entity;
    if (!isEntityValid(entity)) continue;
    try {
      entity.teleport(entity.location, {
        rotation: { x: saved.rotation.x, y: saved.rotation.y },
        keepVelocity: true
      });
    } catch {}
  }
  session.originalRotations.clear();
}

function stopSession(key, session) {
  try {
    if (session.runId !== undefined) system.clearRun(session.runId);
  } catch {}
  restoreMobRotations(session);
  activeSessions.delete(key);
}

function danceMob(entity, session, finale) {
  if (!isDanceable(entity)) return;
  rememberRotation(session, entity);

  const kind = mobKind(entity);
  const mode = session.mode;
  const chill = mode === "chill";
  const battle = mode === "battle";
  const finaleBoost = finale ? 1.5 : 1;
  let turn = chill ? 5 : battle ? 42 : 28;

  if (SWAYING_MOBS.has(kind)) {
    // Grazers and companion animals get a gentle side-to-side dance.
    turn = (session.step % 2 === 0 ? 1 : -1) * (chill ? 3 : battle ? 24 : 13);
  } else if (FLYING_MOBS.has(kind)) {
    // Flying mobs twirl and sparkle without being pushed upward.
    turn = chill ? 5 : battle ? 48 : 30;
  } else if (ROBOT_MOBS.has(kind)) {
    // Undead and hostile mobs get a deliberately jerky, robotic turn.
    turn = chill ? 7 : battle ? 58 : 36;
  } else if (HOPPING_MOBS.has(kind)) {
    turn = chill ? 4 : battle ? 50 : 24;
  }

  try {
    const rotation = entity.getRotation();
    entity.teleport(entity.location, {
      rotation: { x: rotation.x, y: rotation.y + turn * finaleBoost },
      keepVelocity: true
    });
  } catch {}

  const hopInterval = chill ? 6 : 2;
  const shouldHop = !FLYING_MOBS.has(kind) && session.step % hopInterval === 0;
  if (shouldHop) {
    try {
      const height = finale ? 0.28 : chill ? 0.12 : battle ? 0.26 : 0.2;
      entity.applyImpulse({ x: 0, y: height, z: 0 });
    } catch {}
  }

  if (!chill && session.step % (battle ? 1 : 4) === 0) {
    try {
      entity.addEffect("jump_boost", 6, {
        amplifier: battle ? 1 : 0,
        showParticles: false
      });
    } catch {}
  }

  const particleInterval = chill ? 6 : battle ? 1 : 2;
  if (session.step % particleInterval === 0 || finale && session.step % 2 === 0) {
    try {
      const particle = PARTICLES[session.step % PARTICLES.length];
      dimensionSafeParticle(entity, particle, finale);
    } catch {}
  }
}

function dimensionSafeParticle(entity, particle, finale) {
  const location = entity.location;
  const dimension = entity.dimension;
  dimension.spawnParticle(particle, {
    x: location.x,
    y: location.y + (finale ? 1.2 : 1),
    z: location.z
  });
}

world.afterEvents.playerInteractWithBlock.subscribe((event) => {
  const block = event.block;
  const player = event.player;
  if (!block || block.typeId !== FIGURINE_BLOCK || !player) return;

  const dimension = block.dimension;
  const blockLocation = block.location;
  const location = {
    x: blockLocation.x + 0.5,
    y: blockLocation.y + 0.5,
    z: blockLocation.z + 0.5
  };
  const key = sessionKey(dimension, blockLocation);

  // Sneak-interacting cycles the mode for the next activation.
  if (player.isSneaking) {
    const mode = nextMode(key);
    try {
      player.sendMessage("Melody Figurine mode set to " + MODE_LABELS[mode] + ".");
    } catch {}
    return;
  }

  if (activeSessions.has(key)) {
    try { player.sendMessage("The Melody Figurine is already playing."); } catch {}
    return;
  }

  const mode = selectedModes.get(key) || "party";
  const session = {
    elapsed: 0,
    step: 0,
    mode,
    runId: undefined,
    originalRotations: new Map()
  };
  activeSessions.set(key, session);

  try {
    dimension.playSound(SOUND_ID, location, { volume: 1.0, pitch: 1.0 });
  } catch (error) {
    try {
      player.sendMessage("Melody Figurine could not play its song. Check that the Resource Pack is active and the Music volume is turned up.");
      player.sendMessage(String(error));
    } catch {}
  }

  try {
    player.sendMessage("Melody Figurine started: " + MODE_LABELS[mode] + ". Sneak-interact to change the mode for next time.");
  } catch {}

  session.runId = system.runInterval(() => {
    session.elapsed += UPDATE_INTERVAL_TICKS;
    session.step += 1;

    const finale = session.elapsed >= SONG_DURATION_TICKS - FINALE_TICKS;
    const musicOnly = mode === "music";

    let nearby = [];
    try {
      nearby = dimension.getEntities({ location, maxDistance: DANCE_RADIUS });
    } catch {}

    if (!musicOnly) {
      for (const entity of nearby) danceMob(entity, session, finale);
    }

    animateFigurine(dimension, location, session.step, mode, finale);

    if (!musicOnly && (mode !== "chill" || session.step % 2 === 0)) {
      let nearbyPlayers = [];
      try {
        nearbyPlayers = dimension.getPlayers({ location, maxDistance: DANCE_RADIUS });
      } catch {}
      for (const nearbyPlayer of nearbyPlayers) pulsePlayer(nearbyPlayer, session.step, mode, finale);
    }

    if (session.elapsed >= SONG_DURATION_TICKS) {
      // Return surviving mobs to their original facing and stop all recurring effects.
      stopSession(key, session);
      try {
        for (const nearbyPlayer of dimension.getPlayers({ location, maxDistance: DANCE_RADIUS })) {
          nearbyPlayer.sendMessage("The Melody Figurine party has ended.");
        }
      } catch {}
    }
  }, UPDATE_INTERVAL_TICKS);
});

# Melody Figurine — A Musical Mob Dance

**By ALNStudios**

[![Minecraft Bedrock](https://img.shields.io/badge/Minecraft%20Bedrock-Stable%20Release-brightgreen?style=flat-square&logo=minecraft)](https://github.com/AllensCreations/MCPE-Curseforges)

Place the Melody Figurine and interact with it to start its included soundtrack. Nearby mobs within 20 blocks dance with different movement styles, colorful particles, and a short finale. The figurine gains orbiting musical sparkles while the song plays.

## Overview

The Melody Figurine is a small decorative statue with a matching inventory icon and placed-block texture. Choose from four party modes to set the mood for each activation.

## Key Features

### Included Song
- Interacting with the figurine starts its bundled soundtrack.
- The song is intended to play once rather than loop.
- The dance session is configured for approximately 66 seconds to match the current soundtrack timing.

### Four Party Modes
- **Party Mode:** Frequent spins, hops, colorful particles, and rainbow screen fades.
- **Chill Mode:** Gentler movement with less frequent particles and screen fades.
- **Dance Battle:** Faster turns, more frequent visual effects, and a stronger finale.
- **Music Only:** Plays the song and figurine sparkle effect without forcing nearby mobs to dance or applying screen-color effects.

### Selecting a Mode
- Sneak-interact with the figurine to cycle through the four modes.
- The selected mode is used the next time you activate the figurine.
- Interact normally to start the song and selected mode.

### Nearby Mob Dance
- Nearby mobs within a 20-block radius can join while the session is active.
- Hopping mobs, animals, flying mobs, and many hostile mobs use different simulated movement styles.
- Colorful particles appear around dancing mobs.
- Surviving mobs are returned to their original facing direction when the session ends.
- Players, dropped items, projectiles, armor stands, and vehicles are excluded from mob dance effects.

### Rainbow Screen Effects
- Party Mode and Dance Battle use brief, changing rainbow screen fades; Chill Mode uses them less often.
- The screen-fade effect does not provide true transparency or a direct opacity control. Short fades are used to limit how long the color obscures the view, but the effect is not a genuinely transparent overlay.
- Music Only does not apply screen-color effects.

### Animated Musical Figurine
- Musical sparkles orbit near the figurine while the song plays.
- During the final five seconds, the figurine gains a more energetic particle burst.
- The placed statue model itself remains stationary; the small animation is created with particles around it.

## How to Use

1. Import the add-on and enable both packs in your world settings.
2. Obtain the Melody Figurine from the Creative inventory.
3. Place it on the ground.
4. Sneak-interact to choose a mode, then interact normally to start the song and effects.
