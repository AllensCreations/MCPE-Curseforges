# mcpe-pack-update: Update Spec Delivery

## Authority

- `INSTRUCTIONS.md` is the policy source. `PACK_GENERATOR_INSTRUCTIONS.md` is its standalone copy for generation. The script flow is `INSTRUCTIONS.md` "Termux Script Rules", built with `scripts/make_update_script.py`. Where to look each rule up: the `mcpe-context7` skill. This skill is a short working checklist and never restates or overrides them.
- **Precedence** (as in `PACK_GENERATOR_INSTRUCTIONS.md`): factual accuracy and the user's requested scope, then Part 1, then Part 2, then this skill. Part 4 of the generator file never overrides Parts 1 and 2.
- If these files disagree with each other or with a script in `scripts/`, tell the user exactly what differs instead of choosing silently. If `INSTRUCTIONS.md` cannot be read, stop and report it instead of working from memory.
- Achievements line (every project type): always `Yes, achievement-friendly.` Keep any cheats or world-setting caveat as a following sentence.

## Scope

- Use for changes to an existing project (`MCPEDL/Addons|Maps|Script|Minigame/<Name>/`), a workflow, a script, a catalog or any repo doc.
- Read-only audit or report: use `checkrm`.
- New project from an idea: follow `PACK_GENERATOR_INSTRUCTIONS.md` Part 4 (ask the type first, base64 payload).

## Procedure

1. Read `INSTRUCTIONS.md` Parts 1 and 2 before writing anything, through Context7 as the `mcpe-context7` skill says. `make_update_script.py` and `apply_update.py` are complete in the pack's review zip (`<Pack>.zip`) under `files/`; run them from there.
2. Find the destination folder: the path the user named, otherwise the matching project folder. Do not substitute a similar name; report ambiguity or a missing target. Ask at most one question, and only if the answer changes gameplay, compatibility, distribution, data loss or versioning.
3. Read the real source (manifests, scripts, items, recipes, loot tables, functions, lang files) before writing any claim. Source priority when sources disagree, and report the disagreement: the project's own files, Mojang Bedrock Samples, official Minecraft Creator Documentation, Minecraft Wiki, Bedrock Wiki.
4. Make the smallest possible change. No unrelated rewrites. Never invent features, versions, links, assets, test results or compatibility. Never write comments in shipped `.js`, `.mcfunction` or `.json` files.
5. Write the spec (below), test it (below), then reply (below). For changes to an existing project, never deliver a .sh: this overrides any older "deliver the .sh" wording. A NEW pack still follows `mcpe-new-pack` and delivers its generated .sh.

## The spec

File name: `spec_vN.txt`, a downloadable file. N = CURRENT VERSION + 1, read from the attached repo export, never guessed. The user builds the .sh on their phone with `scripts/make_update_script.py`.

Format (`scripts/apply_update.py`):

- Start: `@@ version vN`, then `@@ project MCPEDL/<Category>/<Name>`, then one `@@ file <path relative to the project>` block per file.
- Directives: replace/with, replace-all, insert-after, insert-before, delete, append, create, overwrite, changelog. Remove files with `@@ delete-file <repo-root path>`.
- Small change: replace/insert only. Anchors are copied from the attached export, never from memory, and must occur exactly once. Do not end an anchor with a newline.
- Large redesign: `@@ overwrite` (new content must exceed 60% of the old file) or `@@ create` for new files. Never many fragile edits.
- A content line that starts with `@@` is written `@@@`.
- End with `@@ changelog <Update Name>` using `### Added`, `### Improved & Balanced`, `### Fixed` and `- **Title**: text`. Never touch manifest versions or README links.
- New pixel textures: `@@ create` the pixel JSON under `texture_sources/`, then add the PNG step to the Termux commands.
- Keep README.md and DESCRIPTION.md accurate (INSTRUCTIONS Part 2 template). Never claim an in-game test.

**Test before delivering.** Apply the spec to the export text in the sandbox with `apply_update.py` (`--dry-run`, then a real run on a copy). Check every anchor, validate each changed JSON, run `node --check` on JS. Report every check not run.

## Versions

- N is the current version from the attached export plus one. `apply_update.py` rejects a stale version, so a stale spec cannot run on a newer repo.
- Never edit manifest versions or the README version or download link. The auto-version-bump workflow does that on push.

## Docs

- The changelog entry is mandatory on every update and is written with the final `@@ changelog <Update Name>` directive. Never edit or delete older entries; correct them in the new entry.
- After the change, check the README.md and DESCRIPTION.md in the destination. Edit them only if the change makes them inaccurate or incomplete. Never remove verified content.
- Follow the Part 2 templates in `INSTRUCTIONS.md` exactly (`scripts/doc_template.py` fails the build on deviation): same headings, same heading text, same order, same labels, no added sections, no boilerplate, no placeholders. README is version-free and DESCRIPTION has no release version in its title.
- Writing, layout, attribution, keywords and the README and DESCRIPTION templates are defined in `INSTRUCTIONS.md` Part 2. Read them there; do not copy them into the script from memory.

// First join: builds the island, starter chest and spawn point, tags the player, and shows the first tip.
import { world, system, ItemStack } from "@minecraft/server";
import { LUCKY, TIP_KEY, BUILT_KEY, SETUP_TAG, CORE, SPAWN_BLOCK, SPAWN_STAND, CHEST_AT, STARTER } from "./config.js";

let setupRunning = false;

function blockAt(dimension, x, y, z) {
  const block = dimension.getBlock({ x, y, z });
  if (!block) throw new Error("chunk not loaded");
  return block;
}

function buildIsland() {
  const dimension = world.getDimension("overworld");
  for (let x = -16; x <= 16; x++) {
    for (let z = -16; z <= 16; z++) blockAt(dimension, x, -64, z).setType("minecraft:air");
  }
  blockAt(dimension, 0, 63, 0).setType("minecraft:bedrock");
  for (let x = -1; x <= 1; x++) {
    for (let z = -1; z <= 1; z++) blockAt(dimension, x, 64, z).setType("minecraft:grass_block");
  }
  blockAt(dimension, CORE.x, CORE.y, CORE.z).setType(LUCKY);
  const chest = blockAt(dimension, CHEST_AT.x, CHEST_AT.y, CHEST_AT.z);
  chest.setType("minecraft:chest");
  const container = chest.getComponent("minecraft:inventory")?.container;
  if (!container) throw new Error("chest inventory missing");
  STARTER.forEach(([id, amount], slot) => container.setItem(slot, new ItemStack(id, amount)));
  world.setDefaultSpawnLocation(SPAWN_BLOCK);
  world.setDynamicProperty(BUILT_KEY, true);
}

function runSetup(player, tries) {
  try {
    buildIsland();
    player.teleport(SPAWN_STAND);
    player.addTag(SETUP_TAG);
    setupRunning = false;
  } catch (e) {
    if (tries >= 15) {
      setupRunning = false;
      return;
    }
    system.runTimeout(() => runSetup(player, tries + 1), 20);
  }
}

export function registerIsland() {
  world.afterEvents.playerSpawn.subscribe(({ player, initialSpawn }) => {
    if (!initialSpawn || world.getDynamicProperty(TIP_KEY)) return;
    world.setDynamicProperty(TIP_KEY, true);
    system.runTimeout(() => {
      try {
        player.onScreenDisplay.setActionBar("§6Break the lucky block under you. Open the chest first. The first 20 breaks are a safe tutorial.");
      } catch (e) {
        return;
      }
    }, 100);
  });

  world.afterEvents.playerSpawn.subscribe(({ player, initialSpawn }) => {
    if (!initialSpawn || setupRunning) return;
    try {
      if (player.hasTag(SETUP_TAG)) return;
      if (world.getDynamicProperty(BUILT_KEY)) {
        player.addTag(SETUP_TAG);
        return;
      }
    } catch (e) {
      return;
    }
    setupRunning = true;
    system.runTimeout(() => runSetup(player, 0), 20);
  });
}

export function takeTutorial() {
  const raw = tutorialRaw();
  if (raw === "done") return null;
  const left = typeof raw === "string" && raw.length > 0 ? raw.split(",").map(Number) : TUTORIAL.map((entry, index) => index);

// Picks the next lucky block type for the center spot, using each type's weight.
import { LUCKY, TYPES } from "./config.js";
import { tutorialActive } from "./tutorial.js";

export function nextBlockId() {
  if (tutorialActive()) return LUCKY;
  const ids = Object.keys(TYPES);
  let roll = Math.random() * ids.reduce((sum, id) => sum + TYPES[id].weight, 0);
  for (const id of ids) {
    roll -= TYPES[id].weight;

// Entry point: wires the break event, the lucky block safety timer and the island setup together.
import { world, system } from "@minecraft/server";
import { TYPES, CORE, SETUP_TAG } from "./lib/config.js";
import { rand } from "./lib/helpers.js";
import { PRIZES } from "./lib/prizes.js";
import { takeTutorial, showTutorial } from "./lib/tutorial.js";
import { nextBlockId } from "./lib/types.js";
import { registerIsland } from "./lib/island.js";

function announce(ctx, prize) {
  const good = prize[1] === "g";
  const line = `${ctx.type.label}§r §7${ctx.type.chance}% §8|§r ${good ? "§a" : "§c"}${prize[0]}`;
  try {
    ctx.player.onScreenDisplay.setActionBar(line);
    ctx.player.playSound(good ? "random.levelup" : "note.bass");
    ctx.dimension.spawnParticle(good ? "minecraft:villager_happy" : "minecraft:villager_angry", ctx.top);
  } catch (e) {
    return;
  }
}

function trigger(player, dimension, loc, type) {
  const ctx = { player, dimension, loc, type, top: { x: loc.x + 0.5, y: loc.y + 1.2, z: loc.z + 0.5 } };
  const pool = type.theme ? PRIZES.filter((p) => p[2].includes(type.theme)) : PRIZES;
  for (let attempt = 0; attempt < 6; attempt++) {
    const prize = pool[rand(pool.length)];
    try {
      prize[3](ctx);
    } catch (e) {
      continue;
    }
    announce(ctx, prize);
    return;
  }
}

world.afterEvents.playerBreakBlock.subscribe((event) => {
  const type = TYPES[event.brokenBlockPermutation.type.id];
  if (!type) return;
  const { player, dimension, block } = event;
  const loc = { x: block.location.x, y: block.location.y, z: block.location.z };
  const isCore = dimension.id === "minecraft:overworld" && loc.x === CORE.x && loc.y === CORE.y && loc.z === CORE.z;
  system.run(() => {
    const step = isCore ? takeTutorial() : null;
    if (isCore) {
      const target = dimension.getBlock(loc);
      if (target && target.isAir) target.setType(nextBlockId());
    }
    if (step) showTutorial(player, dimension, loc, step);
    else trigger(player, dimension, loc, type);
  });
});

system.runInterval(() => {
  if (world.getPlayers({ tags: [SETUP_TAG] }).length === 0) return;
  try {
    const block = world.getDimension("overworld").getBlock(CORE);
    if (block && block.isAir) block.setType(nextBlockId());
  } catch (e) {
    return;
  }
}, 100);

registerIsland();

# One Block Skyblock Lucky Blocks — A single lucky block on a 3x3 void island

**By ALNStudios**

[![Minecraft Bedrock](https://img.shields.io/badge/Minecraft%20Bedrock-Stable%20Release-brightgreen?style=flat-square&logo=minecraft)](https://github.com/AllensCreations/MCPE-Curseforges)

**Break the one lucky block on a 3x3 void island and win one of 250 prizes, each with the same chance.**

> The center block comes back as one of 7 types, each with its own texture and a prize list that matches its purpose. Surprises such as a falling anvil or a loot chest struck by lightning keep every break exciting.

## Overview

You start on a 3x3 grass island floating in an empty void, standing on a single lucky block in the center. Break it and it returns in the same spot as a random type: All-Round, Farming, Building, Combat, Mining, Mystic or Treasure. Every break gives a prize: items, food, tools, friendly animals, potion effects, or a small setback such as a hostile mob or a short danger.

## Key Features

### One Central Lucky Block
- **What Happens**: The lucky block sits at the center of the island and is replaced the moment you break it, with a random type from the pool.
- **Good To Know**: If the center spot ever becomes empty, a lucky block is placed there again within about 5 seconds.

### 7 Lucky Block Types
- **What Happens**: The types are All-Round, Farming, Building, Combat, Mining, Mystic and Treasure. Each has its own texture with a symbol on the sides and top.
- **Good To Know**: A themed block gives prizes from its own list, such as saplings and food from Farming or swords and armor from Combat. The All-Round block can give any prize. After the tutorial, Building is the most common type at 20% of blocks and Treasure is the rarest at 9%.

### 20-Break Tutorial
- **What Happens**: The first 20 breaks of the center block give 20 fixed, safe rewards in random order: wood, planks, sticks, a crafting table, wooden tools, leather armor, building blocks, a furnace, torches, food, seeds, saplings, a water bucket, a bed and farm animals.
- **Good To Know**: Each tutorial break shows its number and a short tip on the action bar, and no setbacks happen. During the tutorial the center block is always the All-Round type.

### 250 Equal Prizes
- **What Happens**: In the All-Round block every one of the 250 prizes has the same 0.4% chance. A themed block picks equally among the prizes of its own list.
- **Good To Know**: 198 prizes are rewards and 52 are setbacks, so about 79% of All-Round breaks give a reward. The same prize can come twice in a row.

### Physical Surprises
- **What Happens**: Falling Anvil warns you on the action bar, then drops one anvil about 5 blocks above you, and it is removed a few seconds after it lands. Thunder Pig and Thunder Villager summon a mob and call lightning on it about a quarter of a second later.
- **Good To Know**: Lightning strikes close to the island, so it can hurt you and set you on fire.

### Baby Shower
- **What Happens**: About 10 baby cows, pigs, sheep and chickens spawn around the island.

### Falling Chest
- **What Happens**: A loot chest falls from about 8 blocks up onto a free spot next to the center block and holds 5 stacks of loot. Lightning strikes it 5 seconds after it lands.
- **Good To Know**: Anything still inside when the lightning hits is spilled on the ground at the chest spot.

### Starter Chest
- **What Happens**: A chest waits on a corner of the island with 3 Oak Saplings, 4 Bone Meal, 4 Bread and a Bucket.
- **Good To Know**: The first time you join, a short action bar tip tells you to break the lucky block and open the chest.

### Action Bar Results
- **What Happens**: Each prize shows on the action bar with the block type, its chance of appearing and the prize name, and nothing is written in chat. Tutorial breaks show their number and a tip instead.

## How to Use

1. Open the world and wait a moment while the island appears; you spawn standing on the lucky block in the center, so look down to break it.
2. Read the prize on the action bar, then pick up what dropped or deal with what appeared.
3. Open the chest on the corner for your first saplings and tools.
4. Follow the 20-break tutorial, then keep breaking the block that comes back and try each type.

## Common Questions

- **Does the lucky block run out?**: No. It is placed again each time it is broken, so you can keep going without limit.
- **Can I choose the type?**: No. The type is random each time the block comes back.
- **Do the prizes get better as I go?**: No. After the 20-break tutorial every break draws from the same list, so any prize can come at any time.
