# mcpe-pack-update: Update Spec Delivery

## Authority

- `INSTRUCTIONS.md` is the policy source. `PACK_GENERATOR_INSTRUCTIONS.md` is its standalone copy for generation. The script flow is `INSTRUCTIONS.md` "Termux Script Rules", built with `scripts/make_update_script.py`. Where to look each rule up: the `mcpe-context7` skill. This skill is a short working checklist and never restates or overrides them.
- **Precedence** (as in `PACK_GENERATOR_INSTRUCTIONS.md`): factual accuracy and the user's requested scope, then Part 1, then Part 2, then this skill. Part 4 of the generator file never overrides Parts 1 and 2.
- If these files disagree with each other or with a script in `scripts/`, tell the user exactly what differs instead of choosing silently. If `INSTRUCTIONS.md` cannot be read, stop and report it instead of working from memory.
- Achievements line (every project type): always `Yes, achievement-friendly.` Keep any cheats or world-setting caveat as a following sentence.

## Scope

- Use for changes to an existing project (`MCPEDL/Addons|Maps|Script|Minigame/<Name>/`), a workflow, a script, a catalog or any repo doc.
- Read-only audit or report: use `checkrm`.
- New project from an idea: follow `PACK_GENERATOR_INSTRUCTIONS.md` Part 4 (ask the type first, base64 payload).

## Procedure

1. Read `INSTRUCTIONS.md` Parts 1 and 2 before writing anything, through Context7 as the `mcpe-context7` skill says. `make_update_script.py` and `apply_update.py` are complete in the pack's review zip (`<Pack>.zip`) under `files/`; run them from there.
2. Find the destination folder: the path the user named, otherwise the matching project folder. Do not substitute a similar name; report ambiguity or a missing target. Ask at most one question, and only if the answer changes gameplay, compatibility, distribution, data loss or versioning.
3. Read the real source (manifests, scripts, items, recipes, loot tables, functions, lang files) before writing any claim. Source priority when sources disagree, and report the disagreement: the project's own files, Mojang Bedrock Samples, official Minecraft Creator Documentation, Minecraft Wiki, Bedrock Wiki.
4. Make the smallest possible change. No unrelated rewrites. Never invent features, versions, links, assets, test results or compatibility. Never write comments in shipped `.js`, `.mcfunction` or `.json` files.
5. Write the spec (below), test it (below), then reply (below). For changes to an existing project, never deliver a .sh: this overrides any older "deliver the .sh" wording. A NEW pack still follows `mcpe-new-pack` and delivers its generated .sh.

## The spec

File name: `spec_vN.txt`, a downloadable file. N = CURRENT VERSION + 1, read from the attached repo export, never guessed. The user builds the .sh on their phone with `scripts/make_update_script.py`.

Format (`scripts/apply_update.py`):

- Start: `@@ version vN`, then `@@ project MCPEDL/<Category>/<Name>`, then one `@@ file <path relative to the project>` block per file.
- Directives: replace/with, replace-all, insert-after, insert-before, delete, append, create, overwrite, changelog. Remove files with `@@ delete-file <repo-root path>`.
- Small change: replace/insert only. Anchors are copied from the attached export, never from memory, and must occur exactly once. Do not end an anchor with a newline.
- Large redesign: `@@ overwrite` (new content must exceed 60% of the old file) or `@@ create` for new files. Never many fragile edits.
- A content line that starts with `@@` is written `@@@`.
- End with `@@ changelog <Update Name>` using `### Added`, `### Improved & Balanced`, `### Fixed` and `- **Title**: text`. Never touch manifest versions or README links.
- New pixel textures: `@@ create` the pixel JSON under `texture_sources/`, then add the PNG step to the Termux commands.
- Keep README.md and DESCRIPTION.md accurate (INSTRUCTIONS Part 2 template). Never claim an in-game test.

**Test before delivering.** Apply the spec to the export text in the sandbox with `apply_update.py` (`--dry-run`, then a real run on a copy). Check every anchor, validate each changed JSON, run `node --check` on JS. Report every check not run.

## Versions

- N is the current version from the attached export plus one. `apply_update.py` rejects a stale version, so a stale spec cannot run on a newer repo.
- Never edit manifest versions or the README version or download link. The auto-version-bump workflow does that on push.

## Docs

- The changelog entry is mandatory on every update and is written with the final `@@ changelog <Update Name>` directive. Never edit or delete older entries; correct them in the new entry.
- After the change, check the README.md and DESCRIPTION.md in the destination. Edit them only if the change makes them inaccurate or incomplete. Never remove verified content.
- Follow the Part 2 templates in `INSTRUCTIONS.md` exactly (`scripts/doc_template.py` fails the build on deviation): same headings, same heading text, same order, same labels, no added sections, no boilerplate, no placeholders. README is version-free and DESCRIPTION has no release version in its title.
- Writing, layout, attribution, keywords and the README and DESCRIPTION templates are defined in `INSTRUCTIONS.md` Part 2. Read them there; do not copy them into the script from memory.

## Reply

1. `spec_vN.txt` as a downloadable file.
2. These Termux commands, with N and the project filled in:

```
cd ~/MCPE-Curseforges && git checkout -- Package changelog_views && git pull --rebase --autostash
python3 scripts/make_update_script.py ~/storage/downloads/spec_vN.txt --out-dir ~/storage/downloads --verify ~/MCPE-Curseforges
bash ~/storage/downloads/<Name>_vN_*.sh
```

Only when textures changed, then:

```
python3 scripts/pixel_json_to_png.py MCPEDL/<Category>/<Name>
git add MCPEDL/<Category>/<Name>/resource_pack/textures
git commit -m "<short>" && git pull --rebase --autostash && git push
```

3. Two or three sentences: what changed, which checks ran, what is unverified. Add `Docs queried (YYYY-MM-DD): <library IDs and topics>`.
4. **Save in AI memory**: Every finished output, applied change summary, and spec version must be retained in AI memory/scratch notes so context is preserved across turns without relying on session replay.

import { ItemStack } from "@minecraft/server";
import { IDS, VALUE, KEYS } from "./config.js";

export const inventoryOf = (player) => player.getComponent("inventory")?.container;

export function getBalance(player) {
  const v = player.getDynamicProperty(KEYS.vault);
  return typeof v === "number" && v > 0 ? Math.floor(v) : 0;
}

export function setBalance(player, value) {
  player.setDynamicProperty(KEYS.vault, Math.max(0, Math.floor(value)));
}

export function breakdown(value) {
  const c = Math.floor(value / 100);
  const rest = value - c * 100;
  const g = Math.floor(rest / 10);
  return { c, g, s: rest - g * 10 };
}

export function describeValue(value) {
  const b = breakdown(value);
  const parts = [];
  if (b.c) parts.push(`§a${b.c} Cursed`);
  if (b.g) parts.push(`§6${b.g} Gold`);
  if (b.s || !parts.length) parts.push(`§f${b.s} Silver`);
  return parts.join("§r§f, ");
}

export function looseCounts(player) {
  const counts = { [IDS.silver]: 0, [IDS.gold]: 0, [IDS.cursed]: 0 };
  const c = inventoryOf(player);
  if (!c) return counts;
  for (let i = 0; i < c.size; i++) {
    const it = c.getItem(i);
    if (it && it.typeId in counts) counts[it.typeId] += it.amount;
  }
  return counts;
}

export const countsValue = (counts) =>
  Object.keys(counts).reduce((sum, k) => sum + VALUE[k] * counts[k], 0);

export function takeLoose(player, typeId, amount) {
  const c = inventoryOf(player);
  if (!c) return 0;
  let left = amount;
  for (let i = 0; i < c.size && left > 0; i++) {
    const it = c.getItem(i);
    if (!it || it.typeId !== typeId) continue;
    if (it.amount <= left) {
      left -= it.amount;
      c.setItem(i, undefined);
    } else {
      it.amount -= left;
      c.setItem(i, it);
      left = 0;
    }
  }
  return amount - left;
}

export function giveStack(player, stack) {
  const c = inventoryOf(player);
  const rest = c ? c.addItem(stack) : stack;
  if (rest) player.dimension.spawnItem(rest, player.location);
}

export function giveAmount(player, typeId, amount, decorate) {
  let left = amount;
  while (left > 0) {
    const n = Math.min(64, left);
    const stack = new ItemStack(typeId, n);
    if (decorate) decorate(stack);
    giveStack(player, stack);
    left -= n;
  }
}

export function depositAll(player) {
  const counts = looseCounts(player);
  let total = 0;
  for (const typeId of Object.keys(counts)) {
    if (!counts[typeId]) continue;
    const taken = takeLoose(player, typeId, counts[typeId]);
    total += taken * VALUE[typeId];
  }
  if (total > 0) setBalance(player, getBalance(player) + total);
  return total;
}

export function withdrawCoin(player, typeId, count) {
  const cost = VALUE[typeId] * count;
  if (getBalance(player) < cost) return false;
  setBalance(player, getBalance(player) - cost);
  giveAmount(player, typeId, count);
  return true;
}

export function withdrawAll(player) {
  const value = getBalance(player);
  if (value <= 0) return 0;
  const b = breakdown(value);
  setBalance(player, 0);
  if (b.c) giveAmount(player, IDS.cursed, b.c);
  if (b.g) giveAmount(player, IDS.gold, b.g);
  if (b.s) giveAmount(player, IDS.silver, b.s);
  return value;
}

export function compressLoose(player) {
  const counts = looseCounts(player);
  let s = counts[IDS.silver];
  let g = counts[IDS.gold] + Math.floor(s / 10);
  s %= 10;
  const c = counts[IDS.cursed] + Math.floor(g / 10);
  g %= 10;
  if (s === counts[IDS.silver] && g === counts[IDS.gold] && c === counts[IDS.cursed]) return false;
  takeLoose(player, IDS.silver, counts[IDS.silver]);
  takeLoose(player, IDS.gold, counts[IDS.gold]);
  takeLoose(player, IDS.cursed, counts[IDS.cursed]);
  if (c) giveAmount(player, IDS.cursed, c);
  if (g) giveAmount(player, IDS.gold, g);
  if (s) giveAmount(player, IDS.silver, s);
  return true;
}

## Overview

ALN:PirateTokens adds a three-coin pirate economy built around the Captain's Ledger item. Coins you carry can be lost in a fight with other players, while coins in your Pirate Vault stay safe. Everything is spent through the ledger menus.

## Key Features

### Pirate Token Currency
- **What Happens**: Silver Pirate Tokens, Gold Pirate Doubloons and Cursed Captain's Coins are real stackable items. 10 Silver convert to 1 Gold Doubloon and 10 Gold Doubloons convert to 1 Cursed Captain's Coin.

### Captain's Ledger
- **What Happens**: Craft the ledger from a Book, a Gold Nugget and a Compass, then use it to open a four-option menu: Pirate Vault, Pirate Bounties, Black Market and Mystery Crates.

### Pirate Vault
- **What Happens**: Deposit every carried coin into your personal vault, withdraw 1 or 10 Silver, 1 or 10 Gold, 1 Cursed Coin or everything as the best coins, and compress carried coins upward.

### Ocean and Raider Loot
- **What Happens**: Drowned, Guardians, Elder Guardians, Pillagers, Ravagers and Withers drop tokens. Fishing treasure catches and the first opening of a shipwreck or buried treasure chest also pay out.

### Loose Coin Death Drop
- **What Happens**: If you die carrying coins, half of each coin type (rounded up) drops at your death spot with a coin-scatter sound. Vault savings are never touched.

### Pirate Bounties
- **What Happens**: Three daily bounties such as Drowned Hunter, Deep Sea Angler and Treasure Seeker show live progress. Press Claim Doubloons when one is finished to bank the reward.

### Black Market
- **What Happens**: Spend vault savings on the Treasure Hunter's Compass, the Sea-Dog's Cutlass, Bottled Sea Breeze or three bundles of prismarine, dark oak and treasure materials.

### Mystery Crate Block
- **What Happens**: Craft a dark-wood crate with gold corners from 4 Gold Nuggets, 4 Dark Oak Planks and 1 Gold Pirate Doubloon. Place it anywhere and tap it to open the crate menu. Sneak to build against it.

### Mystery Buccaneer Crates
- **What Happens**: Pay 3 Gold Doubloons or 1 Cursed Captain's Coin from the vault. The prize ticks across the screen with note sounds, then bursts with gold particles and a jackpot title. The menu closes after a win, and 54 prizes come in 5 tiers from Common to Legendary, with a chance list for each crate.

## How to Use

1. Craft a Captain's Ledger with a Book, a Gold Nugget and a Compass.
2. Hunt ocean and raider mobs, fish, or open shipwreck and buried treasure chests to collect coins.
3. Use the ledger and choose Pirate Vault, then Deposit All Coins to bank them.
4. Open Pirate Bounties each day and press Claim Doubloons on finished bounties.
5. Spend vault savings in the Black Market or on a Mystery Crate. Place a Mystery Crate block to open the crate menu without the ledger.
6. Use the Treasure Hunter's Compass to find buried treasure, or sneak and use it to find a shipwreck. Coordinates appear in chat when command feedback is enabled.
