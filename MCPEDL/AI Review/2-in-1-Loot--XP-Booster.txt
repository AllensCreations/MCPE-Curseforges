### 1.3 Version Format and Manifests
**Manifest versioning (Bedrock engine format):** `header.version` MUST be a 3-integer array `[X, Y, Z]` (e.g. `[1, 0, 0]`, `[2, 0, 0]`); `metadata.version` MUST be the string `"X.Y.Z"` (e.g. `"1.0.0"`). The Bedrock engine rejects non-array values or strings like `"vX"` in manifests. NEVER use `vX` syntax inside any `manifest.json` field.
**Per-pack user-facing format:** Every user-visible reference to a version uses `vX` (a single whole number): pack title suffix `(vX)`, changelog headings `## [vX]`, package filenames `(Shortcut VX.ext)`, README download links, CurseForge/MCPEDL release names, snapshot folder prefix `V`. The two formats are strictly separate: manifests = `[X, 0, 0]` / `"X.0.0"`, everything the user sees = `vX`.
- Version = `vX` format (single whole number, e.g. `v2`, `v3`; Bedrock `header.version` maps to `[X, 0, 0]`; legacy `X.Y.Z` supported). NEVER `X.Y.Z.A`. No fourth part, no Alpha. Same version in `metadata.version`, `(vX)` titles, changelog headings, package names, README links, snapshots.

- Update: X+1 (v1 -> v2, v2 -> v3; legacy 1.2.3 converts to v2). Manifest title suffix equals version (e.g. `(v2)`).
- Manifest title = `Add-on Name (vX)` (e.g. `Vanilla Quality of Life (v2)`). Exactly one terminal suffix, equals `header.version` (or major integer), BP/RP match. NEVER duplicate suffixes. `scripts/validate_manifest_titles.py [--project <path>]` fails the job on violation (also notes non-fail: format_version != 2, missing/zero `min_engine_version`, missing `metadata.authors`).

- `header.description` contains `by ALNStudios` exactly once. NEVER attribution in title.
- NEVER change pack UUIDs or world storage keys to rename a title. NEVER regenerate header UUIDs (breaks worlds).
- Build sync: every processed project aligns all source manifests to one highest `X.Y.Z`: `header.version`, `metadata.version`, title suffix, module versions, same-project BP/RP deps. FORCES `metadata.authors` = `["ALNStudios"]` and `metadata.product_type` = `"addon"` in EVERY BP and RP manifest (new packs, updates, builds; NEVER another author or type), optional `metadata.license`. `product_type` `"addon"` is what keeps achievements allowed (owner-confirmed in game). The Bedrock Wiki says Mojang removed this in game 26.50 (MCPE-242529): if a newer game version shows achievements disabled, report it, do not hide it.
- Snapshots: `builds/<pack>/versions/V<X.Y.Z>/` (packages, `source.zip`, `source.sha256`, `build_info.json`). Refreshed when source/packages differ. Last 5 kept.
- NOTHING auto-bumps. The new version is written in CHANGELOG.md AND, in the same update script, into every source manifest with `python3 scripts/manifest_tools.py --project <path> --set vX` (header.version, metadata.version, title suffix, module and dependency versions; UUIDs untouched; never lowers)
, so every update changes the build. Publish to CurseForge uploads the newest changelog version as written and groups every entry since the last publish. The passive build (`Build Changed Packs & Sync Catalogs`) aligns each pack to its highest existing version and rebuilds. `--bump` / `AUTO_BUMP_MANIFEST=true` remain in `scripts/auto_bump_and_build.py` for manual use only.
- Package name: **`(<Shortcut> VX.<ext>)`** (example **`(MiningHelmet V1.mcaddon)`**, or legacy **`(<Shortcut> VX.Y.Z.<ext>)`**). Always format name references in bold with parentheses. Shortcut = short, letters and digits only (NEVER `-`, `_`, spaces, `by ALNStudios`), close to the add-on name, kept in `scripts/pack_shortcuts.json` by project folder (fallback: folder name joined). Custom via `metadata.package_filename` or `PACK_FILENAME_TEMPLATE`; MUST contain `V{version}` and no parenthesis in the file name itself, else the default is used. CurseForge upload copy uses the same name. `python3 scripts/rename_packages.py --check|--apply` renames old packages and repairs references.
- Creator name `ALNStudios`. `python3 scripts/rename_brand.py --apply` migrates old name. NEVER rename lowercase namespaces (`allenscreations:`).
- Tools: `python3 scripts/manifest_tools.py --project <path> --check|--align|--bump` (`--all --check`). `sync_manifest_versions.py`: deps and `min_engine_version` maintenance; set `min_engine_version` by hand after lookup. `sync_project_docs.py` NOT in build: edit DESCRIPTION/CHANGELOG deliberately. `sync_readme_links.py [--check]` repairs README links (runs after every build).
- LOCK: every `MCPEDL/Addons/` project has `LOCK` at root starting `ALNStudios Add-on Lock v1`. Importer creates it, build enforces it. Missing/invalid = release-blocking: report path, NEVER call build-ready. Safeguard only, not encryption.

### 1.12 Vanilla Limits and Workarounds
Applies to every addon, map, script, minigame, item, entity, block, trade, recipe and enchantment, new or updated.
- A hardcoded vanilla limit blocks the requested mechanic (examples: mutually exclusive enchantments, item, entity or component caps, trade or recipe limits) AND the standard approach (behavior JSON, commands, crafting, enchanting) fails: NEVER drop the feature silently. The standard approach works: use it, no workaround.
- Lightest workaround first. 1) Data-driven: custom item, block, entity, recipe, loot, trade, spawn rule, animation controller, tag, component. 2) `@minecraft/server`: custom components, events, ItemStack and Entity APIs, dynamic properties, tags or scoreboard for state. 3) Structural: helper or proxy entity, swapped or replaced item or entity, tiered item variants, `.mcstructure` or template placement, function-driven effects.
- NEVER invent an API, component, event or behavior. Use only what the looked-up stable version (1.2) provides and the repo scripts accept. Cannot verify: say so in DESCRIPTION.md.
- Modular: one small file per workaround with one entry point (script: `behavior_pack/scripts/lib/<name>.js` imported relatively; data: its own function file, entity or item definition). Reuse an existing module. NEVER copy the logic per feature.
- Safe: idempotent setup, caps and cleanup for spawned entities and loops, nothing that corrupts worlds or other packs.
- Conflict Prevention & Isolation:
  1. Custom namespace isolation: Always prefix custom items, blocks, and entities with `aln:<name>` (e.g. `aln:<minigame_name>_controller`).
  2. Avoid Vanilla Entity Overrides: Overriding vanilla entity JSON files (e.g. `entities/zombie.json`) completely wipes out other addons modifying the same entity in Bedrock's load order. Whenever possible, hook into vanilla entity mechanics using `@minecraft/server` Script API event subscriptions (`world.afterEvents.entityDie`, `playerInteractWithEntity`, `entityHurt`, etc.) rather than replacing the vanilla entity JSON.
- Docs (`DOCS_RULES.md`): player-facing result only, no code or API names; the trade-off under Good To Know. State achievement and experiment impact per 1.2.

function readIndex(player, key, levels) {
  const value = player.getDynamicProperty(key);
  if (!Number.isInteger(value) || value < 0) return 0;
  return Math.min(value, levels.length - 1);
}

function getBoost(player) {
  let boost = boosts.get(player.id);
  if (!boost) {
    boost = {
      loot: readIndex(player, LOOT_KEY, LOOT_LEVELS),
      xp: readIndex(player, XP_KEY, XP_LEVELS),
      on: player.getDynamicProperty(ENABLED_KEY) !== false,
      ores: player.getDynamicProperty(ORES_KEY) !== false,
      crops: player.getDynamicProperty(CROPS_KEY) !== false,
      mobs: player.getDynamicProperty(MOBS_KEY) !== false,
    };
    boosts.set(player.id, boost);
  }
  return boost;
}

function lootMultiplier(player) {
  const boost = getBoost(player);
  return boost.on ? LOOT_LEVELS[boost.loot] : 1;
}

function xpMultiplier(player) {
  const boost = getBoost(player);
  return boost.on ? XP_LEVELS[boost.xp] : 1;
}

function blockCategory(typeId) {
  if (GROWTH_RULES[typeId]) return "crops";
  if (typeId.endsWith("_ore") || ORE_EXTRAS.has(typeId)) return "ores";
  return undefined;
}

function isGrown(permutation) {
  const rule = GROWTH_RULES[permutation.type.id];
  if (!rule) return true;
  try {
    return permutation.getState(rule[0]) === rule[1];
  } catch (error) {
    return false;
  }
}

function hasSilkTouch(itemStack) {
  if (!itemStack) return false;
  try {
    const enchantable = itemStack.getComponent("minecraft:enchantable");
    return Boolean(enchantable && enchantable.hasEnchantment("minecraft:silk_touch"));
  } catch (error) {
    return false;
  }
}

function statusLine(player) {
  const boost = getBoost(player);
  const loot = LOOT_LEVELS[boost.loot];
  const xp = XP_LEVELS[boost.xp];
  const skipped = CATEGORIES.filter((category) => !boost[category]).map((category) => CATEGORY_NAMES[category]);
  const skipText = skipped.length > 0 ? `\nLoot skips: ${skipped.join(", ")}` : "";
  if (!boost.on) return `Boosters are off. Saved: Loot up to ${loot}x | XP ${xp}x${skipText}`;
  return `Loot Booster: up to ${loot}x | XP Booster: ${xp}x${skipText}`;

    if (!response.canceled) return response;
    if (response.cancelationReason !== FormCancelationReason.UserBusy) return undefined;

  addIfSupported(form, "header", bold("XP & Loot Booster"));

  addIfSupported(form, "divider");

function distanceSquared(a, b) {
  const dx = a.x - b.x;
  const dy = a.y - b.y;
  const dz = a.z - b.z;
  return dx * dx + dy * dy + dz * dz;
}

function isMob(entity) {
  if (NON_MOB_TYPES.has(entity.typeId)) return false;
  try {
    return !NON_MOB_FAMILIES.some((family) => entity.matches({ families: [family] }));
  } catch (error) {
    return true;
  }
}

function rollMultiplier(max) {
  return 1 + Math.floor(Math.random() * max);
}

function isCreative(player) {
  try {
    return String(player.getGameMode()).toLowerCase() === "creative";
  } catch (error) {

function addToTotals(totals, stack) {
  for (const entry of totals) {
    if (entry.stack.isStackableWith(stack)) {
      entry.amount += stack.amount;
      return;
    }
  }
  totals.push({ stack, amount: stack.amount });
}

function spawnTotals(dimension, location, totals) {
  for (const entry of totals) {
    const size = entry.stack.maxAmount;
    let left = entry.amount;
    while (left > 0) {
      const count = Math.min(size, left);
      const piece = entry.stack.clone();
      piece.amount = count;
      try {
        dimension.spawnItem(piece, location);
      } catch (error) {
        return;
      }
      left -= count;
    }
  }
}

function addExtraBlockLoot(dimension, center, permutation, tool, maxMultiplier, skipSelf) {
  const rounds = rollMultiplier(maxMultiplier) - 1;
  if (rounds <= 0) return;
  const typeId = permutation.type.id;
  const manager = world.getLootTableManager();
  const totals = [];
  for (let round = 0; round < rounds; round++) {
    let stacks;
    try {
      stacks = manager.generateLootFromBlockPermutation(permutation, tool);
    } catch (error) {
      break;
    }
    if (!stacks) break;
    for (const stack of stacks) {
      if (stack.maxAmount <= 1) continue;
      if (skipSelf && stack.typeId === typeId) continue;
      addToTotals(totals, stack);
    }
  }
  spawnTotals(dimension, center, totals);
}

function addExtraMobLoot(player, deadEntity, maxMultiplier) {
  const rounds = rollMultiplier(maxMultiplier) - 1;
  if (rounds <= 0) return;
  let dimension;
  let location;
  let tool;
  try {
    dimension = deadEntity.dimension;
    location = deadEntity.location;
    const equippable = player.getComponent(EntityComponentTypes.Equippable);
    tool = equippable ? equippable.getEquipment("Mainhand") : undefined;
  } catch (error) {
    return;
  }
  const manager = world.getLootTableManager();
  const totals = [];
  for (let round = 0; round < rounds; round++) {
    let stacks;
    try {
      stacks = manager.generateLootFromEntity(deadEntity, tool);
    } catch (error) {
      break;
    }
    if (!stacks) break;
    for (const stack of stacks) {
      if (stack.maxAmount <= 1) continue;
      addToTotals(totals, stack);
    }
  }
  spawnTotals(dimension, location, totals);
}

function blockKey(dimension, location) {
  return `${dimension.id}:${location.x},${location.y},${location.z}`;
}

world.afterEvents.playerInteractWithBlock.subscribe(({ block, itemStack }) => {
  if (!itemStack || itemStack.typeId !== "minecraft:bone_meal") return;
  if (!GROWTH_RULES[block.typeId]) return;
  fertilized.add(blockKey(block.dimension, block.location));
  if (fertilized.size > MAX_FERTILIZED) fertilized.delete(fertilized.values().next().value);
});

world.afterEvents.playerPlaceBlock.subscribe(({ block }) => {
  fertilized.delete(blockKey(block.dimension, block.location));
});

world.afterEvents.playerBreakBlock.subscribe((event) => {
  const { player, block, brokenBlockPermutation, dimension, itemStackBeforeBreak } = event;
  const origin = block.location;
  const wasFertilized = fertilized.delete(blockKey(dimension, origin));

  const maxMultiplier = lootMultiplier(player);
  if (maxMultiplier <= 1) return;
  if (isCreative(player)) return;
  const category = blockCategory(brokenBlockPermutation.type.id);
  if (!category || !getBoost(player)[category]) return;
  if (!isGrown(brokenBlockPermutation)) return;
  if (wasFertilized) return;
  if (hasSilkTouch(itemStackBeforeBreak)) return;

  const center = { x: origin.x + 0.5, y: origin.y + 0.5, z: origin.z + 0.5 };
  addExtraBlockLoot(dimension, center, brokenBlockPermutation, itemStackBeforeBreak, maxMultiplier, category === "ores");
});

world.afterEvents.entityDie.subscribe(({ deadEntity, damageSource }) => {
  const killer = damageSource ? damageSource.damagingEntity : undefined;
  if (!killer || killer.typeId !== "minecraft:player") return;
  if (!isMob(deadEntity)) return;

  const maxMultiplier = lootMultiplier(killer);
  if (maxMultiplier <= 1 || !getBoost(killer).mobs) return;

  addExtraMobLoot(killer, deadEntity, maxMultiplier);
});

function hasNearerPlayer(orbLocation, player, players) {
  const own = distanceSquared(orbLocation, player.location);
  for (const other of players) {
    if (other.id === player.id || !other.isValid) continue;
    if (other.dimension.id !== player.dimension.id) continue;
    if (distanceSquared(orbLocation, other.location) < own) return true;
  }
  return false;
}

system.runInterval(() => {
  const players = world.getAllPlayers();
  for (const player of players) {
    if (!player.isValid) continue;
    const multiplier = xpMultiplier(player);
    if (multiplier <= 1) continue;

    const dimension = player.dimension;
    const location = player.location;
    let orbs;
    try {
      orbs = dimension.getEntities({
        type: "minecraft:xp_orb",
        location,
        maxDistance: XP_RADIUS,
      });
    } catch (error) {
      continue;
    }

    for (const orb of orbs) {
      try {
        if (!orb.isValid) continue;
        const orbLocation = orb.location;
        if (hasNearerPlayer(orbLocation, player, players)) continue;
        if (!orb.hasTag(XP_TAG)) {
          const extra = multiplier - 1;
          orb.addTag(XP_TAG);
          for (let i = 0; i < extra; i++) {
            const bonus = dimension.spawnEntity("minecraft:xp_orb", location);
            bonus.addTag(XP_TAG);
          }
        }
        if (distanceSquared(orbLocation, location) > XP_PICKUP_SQUARED) orb.teleport(location);
      } catch (error) {
        continue;
      }
    }
  }
}, XP_INTERVAL_TICKS);

## Key Features

### Renamed Book Control Panel
- **What Happens**: Rename a Book to "Booster" on an anvil, then right-click with it to open the Booster menu.
- **Good To Know**: Each player keeps their own settings, which are saved between sessions. You can also open the menu with the /aln:booster command.

### Loot Drop Booster
- **What Happens**: Drag the Loot slider across six levels, each giving a random bonus of up to 1x, 2x, 4x, 8x, 16x or 32x, for ores, crops and other Fortune-style blocks you break and for mobs you kill.
- **Good To Know**: Each drop rolls a random bonus up to the level you pick. It works like a Fortune and Looting bonus, but with its own random roll. Ores, gilded blackstone, amethyst clusters, nether wart, sweet berries, wheat, carrots, potatoes, beetroot and mob loot are multiplied, so normal blocks such as dirt, stone and wood drop as usual, and unstackable items such as tools are left alone. Mining with Silk Touch drops the block once and is never multiplied, and blocks broken in Creative mode are not multiplied because they drop nothing. Blocks are boosted by rolling their loot again, so only items that block can really drop are multiplied, and mobs are boosted the same way, using the weapon you killed with, so rare drops stay rare but get more chances to appear. The Ores, Crops and Mobs switches let you choose which kinds of loot are boosted. Crops, nether wart and sweet berries are multiplied only when fully grown, and crops sped up with bone meal are not multiplied. Blocks that drop themselves or can be crafted back from their drops, such as ancient debris, melons, glowstone and sea lanterns, are never multiplied, so they cannot be farmed by placing and breaking. Fortune still works, and the booster multiplies on top of it. Extra drops are combined into full stacks, so large boosts create fewer items on the ground. Only real mobs count, so armor stands, boats, minecarts and mobs that carry items, such as donkeys, mules, llamas, allays, foxes and villagers, are not multiplied, and only mobs you kill yourself are boosted. Only drops that appear the instant you break a block or kill a mob are multiplied, so items thrown or dropped nearby are left alone.

### XP Gain Booster
- **What Happens**: Drag the XP slider across seven levels, 1x, 2x, 4x, 8x, 16x, 32x and 64x, and each XP orb near you is turned into that many orbs.
- **Good To Know**: The orbs are collected instantly, so Mending repairs your gear from the extra XP. Only the orbs closest to you are multiplied, so other players' orbs are never affected.

### About Screen
- **What Happens**: The About button shows the creator, the add-on version, a short note on both packs, the CurseForge and MCPEDL profiles and an unofficial-product notice.

### Redesigned UI
- **What Happens**: A small Resource Pack named Redesigned UI gives the Booster menus the ALNStudios look, with a dark panel, a blue border, a gold title and icon buttons.
- **Good To Know**: Enable the Resource Pack together with the Behavior Pack.

## How to Use

1. Rename a Book to Booster on an anvil.
2. Hold it and right-click, then choose XP & Loot Booster.
3. Drag the Loot and XP sliders, switch Boosters on or off, choose whether Ores, Crops and Mobs are boosted and press Apply. A higher sound means the boosters are on and a lower sound means they are off.

- **Can I turn it off?**: Yes. Open XP & Loot Booster, switch Boosters Off and press Apply. Your levels are kept.
